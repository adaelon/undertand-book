# ADR-0047 跨论文关系由 MCP 客户端运行时编排 / 单篇论文 MCP 只暴露带 LID 证据的自我理解

状态:已接受(2026-07-05,PDF/paper §0.5 跨论文边界)

## 背景
paper profile MVP 的目标是读懂单篇论文。跨论文比较、综述、关系发现会随用户任务变化:同一组论文可被要求比较方法、复现实验、找冲突结论、梳理理论脉络或写 related work。若在预构建期做全局跨论文数据库,会提前引入 corpus identity、paper id、bibliography identity、跨书 graph 和全局检索命令,偏离 MVP。用户提出更自然的形态:用一个 Claude/Codex 等 MCP 客户端同时连接多个论文 MCP,由客户端按任务建立关系。

## 决策
1. **跨论文关系归属 MCP 客户端运行时**:外部 MCP 客户端同时连接多个单篇论文 MCP,通过询问、比较、挑战、综合来建立跨论文关系。
2. **单篇论文 MCP 只暴露本篇自我理解**:每个论文 MCP 负责提供本论文的结构、主张、方法、证据、限制、related-work stance,且所有回答必须带真实 LID 证据。
3. **默认不持久化跨论文数据库**:多论文综合结果默认是会话级产物;只有用户显式保存时,才进入 memory/note。
4. **paper 预构建产物面向可交流性**:预构建应抽取能让单篇论文 agent 对外说清自己的结构化 dossier,而不是构建跨论文 corpus graph。
5. **MCP 客户端适配任意用户需求**:比较维度由用户任务决定,不在预构建期冻结为单一全局关系模型。

## 命门
- **每篇论文先自洽,多篇关系后编排**:单篇 dossier 的质量决定 MCP 交流质量。
- **跨论文结论必须可回溯**:客户端综合时应保留每篇论文返回的 LID citations,否则不得伪装成可验证结论。
- **不把会话综合冒充世界状态**:未显式保存的跨论文关系不进入持久库。

## 否决
- paper MVP 预构建全局 citation graph / corpus graph:范围扩大且需求维度过早冻结。
- 单篇论文 MCP 自行声明跨论文事实:它只拥有本篇证据,不得替其他论文下结论。
- 自动把每次跨论文对话写入持久数据库:会把临时比较、用户试探和未确认综合污染长期状态。

## 何时回头
- 用户频繁重复同一组论文的同一类比较时,评估显式保存的 project-level memory 或 curated corpus workspace。
- 需要团队共享跨论文综述时,另立 ADR 定义人工确认后的 corpus artifact。
- MCP 客户端无法稳定保留多篇 citations 时,先增强返回包形状,不退回预构建全局库。

## 影响
- `CONTEXT.md` 新增 `单篇论文 MCP`、`多论文 MCP 编排`。
- paper profile 预构建继续聚焦单篇论文 dossier 与 LID 证据。
- 后续 Grill 需定义单篇论文 MCP/agent 对外最小可交流包。
