# ADR-0087 Provenance-aware answer delivery and compact provider history

Status: Accepted, amended 2026-07-20.
Extends: ADR-0026 and ADR-0086.
Change type: 边界重构。

### §1 回答来源属性

**决策**:普通回答按信息来源属性判断内部位置泄露,不再把所有与真实 LID 字面相同的数字一律判为 LID。

**否决**:
- 继续匹配全书 LID 字符串:会把正文中的章节号、版本号或其他公开数字误判为内部位置。
- 只匹配 `LID` 前缀:Agent 仍可把结构字段自然化成“第 X 节”或“节点 X”。
- 依赖 Agent 自觉避免 LID:遗漏仍会把内部定位暴露给普通用户。

**命门**:来自 `lid/start_lid/end_lid/anchor_lid/citation_candidate_lids` 等结构字段的值属于内部位置,即使改写成自然语言仍是内部位置;“LID X”“节点 X”等明示内部措辞始终拒绝。来自用户可见文本或已验证规范证据正文的同形数字属于公开文本来源,可跨回合沿用;发生字面碰撞时,明示内部措辞优先拒绝,否则公开文本来源优先允许。
**何时回头**:Provider 能原生返回逐片段、不可伪造的来源标签时,可用原生结构替代 Runtime 的来源属性账本。

### §2 跨回合证据与来源按钮

**决策**:公开文本可作为后续回合的阅读上下文,但用户可见来源引用仍只能由当前回合证据账本创建。

**否决**:
- 把历史 Tool 中出现过的 LID 自动恢复为本轮证据:看过不等于本轮已复验,且历史原文可能失效。
- 新增 `source.recall`:扩大命令面,却没有消除 stale 与归属复验。
- Runtime 自动为位置措辞绑定来源:来源本来是可选的,自动绑定会浪费推理空间并伪造 Agent 的引用意图。

**命门**:Agent 想引用历史位置时重新调用 `book.text` 等证据型工具;必要时可先用 `book.context` 找回位置,但 context 本身不授权引用。只有本轮成功读取并进入证据账本后,才可主动调用 `source.present`。读取失败即失败,不猜最近位置。
**何时回头**:历史来源绑定具备版本化证据快照与显式用户复用语义时。

### §3 自由重写修复与交付诊断

**决策**:来源违规只修复一次;修复可自由重写,最终仍过同一编译闸。

**否决**:
- 要求非违规正文逐字符不变:长回答的空格、标点或 Markdown 漂移会把已消除违规的修复误判为失败。
- 把完整请求消息和 Tool 原文重放给修复模型:重复大上下文,也再次暴露所有内部位置。
- 多次重试或向用户展示内部错误码:前者形成开放式循环,后者泄露实现概念。

**命门**:修复输入仅含原始用户问题、非法候选、每个违规项的位置/形态/来源通道,以及允许使用的来源 ref/标签/预览;模型可以重写整答,但不得调用工具,修复结果必须重新通过同一 marker、source ref 与来源属性编译闸。最终失败只显示“这次回答生成失败，请重试。”。初次与修复后的结构化诊断仅服务端持久,不保存候选全文或思维链。
**何时回头**:真实使用出现明显语义漂移时,改为模型返回结构化替换操作并由 Runtime 确定性应用。

### §4 Provider 历史投影

**决策**:已完成回合的 Tool 调用和结果在发送给 Provider 时投影为类型化历史 Tool 回执;当前活动回合仍保留完整工具结果。

**否决**:
- 永久保留全部历史 Tool 原文:Tool 消息已占历史上下文大头,并持续向后续回合暴露内部 LID。
- 只裁剪 `book.text`:guide、lexicon 等工具在真实历史中同样可主导上下文。
- 改写 `agent-history.json`:破坏持久历史与轨迹诊断真相,也增加迁移风险。

**命门**:回执只保留工具名、定位型参数、成功状态或错误码、证据账本实际接受的范围、已生成 source ref 与不含正文片段的 opaque result digest;不得复用轨迹中截断 Tool 正文的 `result_digest`,不得保留 Tool result body,也不得递归收集结果里出现的全部 LID。投影在读取时追溯适用于旧会话;旧消息无法完整解析时只保留工具名、定位参数、状态和 opaque digest,绝不回退发送原始 Tool 内容。
**何时回头**:Provider 提供受信任的服务端上下文缓存,且能证明不会重复计费、不会向模型暴露已裁剪字段时。

### §5 持久与界面边界

**决策**:历史压缩只改变模型请求投影;持久消息、公开历史 View、轨迹 UI 与选区注入保持现状。

**否决**:
- 同时压缩轨迹:会把诊断面改动混入 provider 上下文优化。
- 合并选区去重:重复选区可能来自用户真实的两次选择,不是历史 Tool 膨胀问题。

**命门**:接受的代价是后续追问偶尔需要一次工具重读;该代价换取显著 token 降幅、更鲜活的证据和更少的 LID 干扰。
**何时回头**:真实使用数据证明重读成本高于历史 Tool 原文的 token 与误导成本时。
