# ADR-0106 异步合并已读账本持久化

Status: Accepted, 2026-08-18.
Revises: ADR-0038 的“真读过即同步直存”时序，不改变已读事实模型。
Extends: ADR-0105 的滚动热路径与批量 I/O 边界。
Change type: [边界重构]。

PHR9 请求瀑布证明，每个 20 叶边缘加载约 99% 的时间耗在正文请求之前：`reader.scroll/goto` 为每个可见 LID 同步执行一次完整 MemoryStore 原子提交。已读事实必须保留，但其磁盘耐久性不再属于导航响应的成功条件。

### §1 导航与账本解耦

**决策**:导航先返回，已读账本后台合并持久化。

**否决**:
- 每 LID fire-and-forget:仍保留重复全量序列化、`sync_all` 与投影重写。
- 独立 Store 并发写同一 JSON:会让笔记、画像与已读快照相互覆盖。
- 删除已读账本:破坏未读前置与阅读旅程的确定性真历史源。

**命门**:导航在同一 AppState 内只登记 `{book_id,lid,touch_count,last_seen}`；Host 于滚动静默期持原 Store 所有权合并成一次原子提交，失败保留队列并重试，切书与有序退出强制冲刷；导航成功不再证明该批记录已落盘。
**何时回头**:若产品要求每次导航响应都具备崩溃耐久性，改用独立增量 WAL 后再恢复强确认，不退回逐 LID 全量快照。
