# ADR-0122 Linux 阅读器宿主与源码部署

Status: Accepted, 2026-09-08；LX0–LX7 已完成，原生构建、宿主、只读就绪、辅助程序、迁入、有序停止、真实 Provider 与完整阅读交互通过；见 [LX7 验收](../Linux阅读器-LX7验收.md)。

修订 [ADR-0001](0001-本地plugin形态.md) 的读时部署位置约束，扩展为用户自有服务器上的单用户阅读；沿用 [ADR-0068](0068-windows-desktop-reader-and-codex-plugin-distribution.md) 的 Web/Server 命令面和 Windows 桌面发行方式。预构建在现有环境完成，Linux 消费已就绪的材料。

## §1 阅读器部署位置

**决策**:Linux 服务器承载单用户阅读器本体。

**否决**:

- 在服务器运行桌面壳：浏览器已能承载阅读界面，额外桌面环境没有必要。
- 为 Linux 另写一套阅读后端：会分叉正文、Agent、笔记和记忆语义。

**命门**:首轮验收使用 veLinux 2.2 CentOS Compat / CentOS Stream 9、x86_64、内核 `5.15.120-5.ve2.x86_64`；复用现有 Rust 服务、Vue 页面与 Provider，书籍就绪仍由既有产物判定。Linux 入口显式选择纯阅读模式，Windows 桌面和 `start.bat` 保留现有阅读、预构建及配置行为；共享代码改动在所属切片通过 Windows 定向回归。
**何时回头**:需要多个独立读者共享一个服务时，重新设计会话和数据所有权。
**展开**:[切片方案](../切片方案-Linux阅读器本体适配.md)、[领域术语](../../CONTEXT.md)。[ADR-0120](0120-whole-source-prebuild-gate-for-formal-learning.md) 的正式学习就绪要求继续成立。

## §2 首版部署交付物

**决策**:以源码目录部署并保留现有读时辅助依赖。

**否决**:

- 首版即要求单二进制发行：阅读统计等现有路径仍调用 TypeScript，会扩大改写范围。
- 只交付静态网页：读时 Agent、导航和私有数据需要现有后端。

**命门**:在最终 Linux 部署目录安装依赖并编译；服务启动环境提供书库、模型和私有数据目录，systemd 管理常驻与有序停止。运行所需 Node/tsx 辅助程序随源码保留，阅读流程不启动预构建。
**何时回头**:源码部署已验收且出现独立安装包需求时，再选择分发形式。
