# ADR-0126 旧批次补位采用当前待办，终态派发正常收束

状态：已接受（2026-09-13，用户确认根因并要求实现、重建插件）。

## 决策

复用派发计划只能复用其组织顺序，不能把旧计划中的任务重新当作当前待办。对于尚未建立派发记录的批次，只要其中有工作单元已不在当前同一已接受计划的待办中，就跳过该旧批次；仍未完成的成员由当前计划重新组织。已经建立的派发继续按其持久进度和收据推进。

派发准备到发布执行入口之间，若持久收据已经表明该派发终结，应正常形成派发终态并重新调度，不再要求生成一个不存在的可执行任务。

命令入口遇到未处理异常时，保存有界的本地诊断，返回无可选恢复操作的 `NEEDS_USER(build_engine_failed)` 与诊断编号。异常正文和堆栈不进入构建主任务；诊断保存失败必须在返回中明确体现。不得伪造完成或自动授予重试。

## 原因与否决

Mastering Rust 的 `unit:81:fragment:0001` 在 21:35:30 已成功；21:38:08 调度器仍从 21:34:43 的旧计划中建立其派发，随后因没有当前工作单元抛错。旧逻辑仅检查当前批次的派发文件，遗漏了别处已经完成的工作；命令入口又丢弃了原异常。

不删除原失败和成功收据，不清空重建，不取消旧计划续调度，不把“任务已完成”当作执行器故障，也不放宽成果有效性判定。当前待办仍由现有输入、策略和成果验证产生。

## 验证与交付

覆盖旧计划未派发成员先完成、部分批次过时后剩余工作重新组织、派发准备后发现终态、以及异常诊断不泄露到主任务。实现与安装记录见 [交付记录](../dispatch-refill-20260913.md)。
