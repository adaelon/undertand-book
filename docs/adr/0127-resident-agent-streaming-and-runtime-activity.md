# ADR-0127 Resident Agent 流式回答与运行活动

状态：已接受，2026-09-13；AS0–AS9 已完成（Linux 实机验收完成于 2026-09-14）。实施入口：[切片方案](../切片方案-Resident-Agent流式回答与运行活动.md)。

改造前，Resident Agent 整轮持有共享状态锁，模型适配器读取完整响应，前端收到最终结果后才显示答案和工具轨迹。一次运行改为独立生命周期，通过增量事件呈现进展；来源编译、Reader/Memory 所有权与持久会话继续承担原有责任。

延续 ADR-0016、0026、0030 的运行时与共享阅读器边界；细化 ADR-0028 的 HTTP 投影，扩展 ADR-0086、0087、0123 的交付过程。模型请求计划与上下文治理沿用 ADR-0091；Windows 桌面与 Linux 单用户宿主沿用 ADR-0122。

## §1 运行所有权

**决策**：一次用户回合对应一个独立 Resident 运行。

**否决**：
- 用 HTTP 连接拥有执行过程：页面断线无法独立恢复观察，停止与连接关闭混为一体。
- 为流式另建一套 Agent 循环：工具权限、预算、来源与评测行为会分叉。

**命门**：复用 turn_id，固定书籍和会话归属；首版每个 Reader 宿主最多一个活动运行，旧 /agent/chat 等待同一核心的终局。
**何时回头**：产品明确支持多个阅读器或多个住户运行同时操作独立状态时。
**展开**：[运行所有权](../切片方案-Resident-Agent流式回答与运行活动.md#2-运行所有权)。

## §2 共享状态边界

**决策**：模型等待在锁外，共享状态按操作读写。

**否决**：
- 整轮加锁后仅推送文本：阅读操作仍被模型等待阻塞。
- 克隆 Reader/Memory 并在终局整体写回：会覆盖运行期间读者的新操作。

**命门**：模型请求、内层查询、综合、画像判断、压缩和来源修复使用固定输入在锁外执行；共享写入只通过当前权威实例，历史按固定 session/turn 提交。
**何时回头**：实测确定性操作的持锁时间已成为主要阅读阻塞时，再拆对应操作。
**展开**：[运行所有权](../切片方案-Resident-Agent流式回答与运行活动.md#2-运行所有权)。

## §3 运行活动

**决策**：运行事实生成事件，界面与轨迹同源。

**否决**：
- 由日志或模型叙述推断工具状态：准备调用与真实执行无法可靠区分。
- 聊天活动和轨迹面板各维护一套状态：顺序、耗时与终态会不一致。

**命门**：工具参数完整且通过既有检查后才进入执行；步骤保留父子关系与真实状态，内层模型调用归属于对应工具；展示摘要从实际结果确定性生成。
**何时回头**：工具执行本身引入并发时，扩展事件的实际调度语义。
**展开**：[事件与展示契约](../切片方案-Resident-Agent流式回答与运行活动.md#3-事件与展示契约)。

## §4 传输与观察恢复

**决策**：运行经 SSE 订阅，以快照衔接断线。

**否决**：
- 重连重新提交问题：可能重复模型请求和阅读副作用。
- 逐 token 持久化事件日志：现有需求由活动快照与终局历史即可满足。

**命门**：控制动作走 HTTP；事件序号按运行递增，有界缓冲与快照在同一序号边界衔接。网络写入不占普通 HTTP 工作线程，也不反向阻塞执行；首版沿用 tiny_http、ureq 和 Vue。
**何时回头**：实际连接规模或快速取消要求超出现有同步传输能力时。
**展开**：[传输与快照](../切片方案-Resident-Agent流式回答与运行活动.md#4-传输与快照)。

## §5 增量答案交付

**决策**：正文增量受控发布，最终编译决定交付。

**否决**：
- 将模型原始分片直接作为答案：会越过出处与来源标记边界。
- 每个分片独立检查后拼接：被拆开的标记及位置表达会漏检。
- 显示完整回答后再播放打字动画：没有减少真实等待。

**命门**：有状态展示投影只发布通过现有公开规则的稳定片段，草稿支持替换；终答仍经完整编译及至多一次既有修复。来源只解析当前运行或持久历史中的已验证绑定。
**何时回头**：支持的真实输出无法以稳定片段增量投影时，调整相应输出合同并保留完整编译权威。
**展开**：[模型分片与回答交付](../切片方案-Resident-Agent流式回答与运行活动.md#5-模型分片与回答交付)。

## §6 终态与停止

**决策**：终态先持久化，取消保留已发生动作。

**否决**：
- 内存结果产生即宣告完成：历史提交失败会造成界面与重开结果不一致。
- 取消回滚整轮或重启自动重放工具：已保存笔记、导航及失败现场失去真实含义。

**命门**：完成、失败和取消均保存运行摘要；停止是协作式，正在停止与已退出分别呈现。进程重启将遗留 pending 明确投影为中断；持久化失败单列为未保存故障，不能宣告持久终态。
**何时回头**：产品明确要求跨进程自动恢复执行，而非恢复观察时。
**展开**：[终态与持久化](../切片方案-Resident-Agent流式回答与运行活动.md#6-终态与持久化)。
