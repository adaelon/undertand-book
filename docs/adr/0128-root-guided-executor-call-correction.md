# ADR-0128 主任务诊断子代理调用并指导纠错

状态：R1–R4 已实现并通过程序、编译安装和实时宿主纠错验收（2026-09-14）；[R4 证据](../performance/understand-book-r4-release.md)。承接 ADR-0117、0121、0125；细化构建主任务的诊断读取边界。

## §1 异常诊断

**决策**：主任务先核对子代理调用，再决定恢复。

**否决**：
- 只信生命周期摘要：参数错误可能被笼统错误码掩盖。
- 遇到不兼容就重新注册：无效参数不证明安装损坏。

**命门**：主任务可读所属子代理的失败操作、控制参数、工具诊断及调用顺序；正文、候选与隐藏推理不进入诊断。缺少记录时明确证据缺口。
**展开**：[诊断与恢复切片方案](../切片方案-主任务诊断子代理调用与纠错恢复.md)。

## §2 调用纠错

**决策**：反馈具体调用错误，按连接状态恢复执行。

**否决**：
- 原样盲重试：重复发送同一错误参数。
- 删除终态去重记录：可能重复打开已有执行或提交。
- 把打开错误计作语义失败：尚未开始内容生成。

**命门**：正确引用取自原派发记录，逐字符比较；可继续的未绑定连接由原子代理纠正，终止或不可复用连接经 Driver 核实未打开、未提交后签发恢复引用，由新执行器携带纠正反馈执行。沿用有限控制恢复次数。
**展开**：[R2–R3](../切片方案-主任务诊断子代理调用与纠错恢复.md)。

## §3 错误分类与权威

**决策**：调用格式错误与协议不兼容分别恢复。

**否决**：
- 将无效引用兜底成 protocol_incompatible：把参数错误升级成安装边界。
- 主任务自行改写失败码：无法解释真实工具返回与恢复依据。

**命门**：工具保留真实诊断，主任务的纠错观察另行表达；Driver 决定恢复代际与完成状态，已有 open/commit 优先。历史笼统错误须有调用证据才进入纠错，真实版本不兼容仍明确报告。
**何时回头**：宿主提供无需模型转写的原生任务绑定时，可替换引用传递方式。
**展开**：[R1、R4](../切片方案-主任务诊断子代理调用与纠错恢复.md)。
