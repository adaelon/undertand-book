## 0 背景与证据边界

目标场景是读者在 iPhone 浏览器中访问 Linux `reader-only` 实例，连续阅读技术材料或论文，选中原文提问，查看回答与来源，并操作 Agent 富呈现内容。此次改造不另建手机版业务栈，而是让同一阅读工作区在不同可用空间中具有适当的呈现方式。

本决策最初依据 2026-09-18 观察到的**当前工作树**形成，包含未提交和未跟踪文件。实施基线 HEAD 为 `8dea7b01290bba136f7332b01b20972d8a9d661f`，但该提交号不是当前工作树的完整快照，也不是 Linux 线上版本证明。MW0–MW3 随后已在同一受保护工作树上实现，并完成 Web 单测、类型检查、生产构建及 Chromium/WebKit 浏览器夹具定向验证；仍没有 iPhone 实机或 Linux 真实入口验收。

## 1 产品决策：单区域优先，对照按任务与空间启用

**决策**：保留同一个 Web 应用、同一套 Reader/Agent API 和业务状态。手机竖屏以单主区域为默认；空间足够且正在进行对照任务时，支持正文与 Agent 双区域。目录、来源预览和短任务按需展开。

| 情形 | 默认呈现 | 明确行为 |
| --- | --- | --- |
| 窄屏连续阅读 | 正文主区域 | 顶部轻量导航；目录不占正文流；问答可直接切换到达 |
| 窄屏查看问答 | 问答主区域 | 保留原读位；打开问答不自动聚焦输入框 |
| 空间足够的对照任务 | 正文＋Agent | 两个区域独立滚动；来源打开后正文定位；不再增加常驻目录第三栏 |
| 宽代码、PDF 或复杂交互内容 | 专注展开 | 由用户显式进入；关闭后回到同一对象与现场 |
| 输入且剩余高度不足 | 输入优先 | 保留引用摘要、编辑和发送入口，临时收敛次要导航 |
| 桌面有足够空间 | 既有宽屏工作区 | 保留目录、阅读器、辅助区及既有鼠标交互，不强迫桌面使用手机导航 |

底部主导航首版为“阅读、问答、笔记、更多”。目录放在顶部入口；成果、画像等通过“更多”进入；公式可从正文进入，轨迹从运行状态进入。横屏低高度下将导航合并为一条紧凑操作带，避免顶部与底部重复占高。功能入口收敛不等于删除能力。

双区域由实际可用宽高、当前任务及用户显示偏好共同决定。物理姿态、CSS `orientation` 或 User-Agent 都不能单独决定布局；`orientation` 表示视口形状，软键盘也可能改变它。[W1]

**否决**：固定桌面虚拟视口后整体缩小；把三栏纵向堆成无限长页面；任何横屏都强制双栏；任何竖屏都常驻半屏聊天；为了适配而删除阅读能力。

**命门**：一次切换可到达问答；关闭辅助区域可回到原读位；空间不足时可退为单区域，但用户选择的对照偏好不因一次键盘或旋转变化被永久覆盖。

## 2 架构决策：逻辑布局与设备侧摆放分离

**决策**：后端 `ReaderLayoutState` 继续表达逻辑工作区。前端增加可测试的设备侧呈现投影，将逻辑内容映射为侧栏、主区域、抽屉或展开层，不制造第二份后端布局真相。

| 所有者 | 负责内容 | 不负责内容 |
| --- | --- | --- |
| Reader/Server | 正式 slot、preset、逻辑焦点、pin、proposal/revision、权威读位及持久状态 | 当前手机的安全区、键盘位置、浏览器工具栏高度 |
| 前端呈现投影 | 可用空间、可见区域、几何尺寸、单区/双区、抽屉位置、本设备显示偏好 | 替后端接受高风险 proposal、变更 profile 能力、伪造 Reader effect |
| 前端交互现场 | 草稿、已冻结选区、返回点、当前查看消息、原生焦点、呈现中的延迟切换 | 长期学习判断、公共书籍真相 |
| RP 既有现场存储 | 特定内容版本的已保存参数、步骤及现场回执 | 整个主应用的任意 DOM 或状态 |

前端投影为纯函数，输入逻辑布局、几何环境、交互状态和显示偏好，输出呈现计划。旋转、工具栏伸缩、键盘变化和纯几何夹紧不提交 `reader.layout.apply`，不递增后端布局 revision，不写学习记忆。

**正式 slot 与普通导航入口必须显式区分。** 当前 RightRail 标签不应被假定为都拥有同名的后端 slot。MW0 列出实际映射；正式 slot 的打开、关闭与配置沿用既有 API，内置阅读/问答导航不凭空创造 slot。因空间不足暂时不显示一个已打开 slot，不等于逻辑上关闭它。

`focus_slot` 仍然是应被呈现的明确请求。没有交互冲突时使目标可见，但不自动弹键盘。输入法组合、原生选区拖动等受保护交互期间可以延迟改变前景区域；UI 应区分“逻辑布局已接受”与“等待当前交互结束后展示”。延迟请求按书籍、会话及 revision 校验，旧请求不能覆盖新用户操作。不得把延迟状态误报为目标已实际可见，也不得每次 resize 重放同一个焦点请求。

**否决**：手机独立布局后端；把全部 UI 瞬态后端化；前端直接接受高风险布局 proposal；旋转时反复提交正式布局命令；Agent 直接操作应用 DOM。

**命门**：后端权威语义不缩水；本设备的摆放偏好不改写另一设备的几何环境。当前 Linux 单实例仍共享当前书与会话，多设备独立阅读不在本决策内。

## 3 连续性决策：保存语义位置，保持核心实例

**决策**：显示变化不等于阅读意图变化。区域切换和旋转优先保留核心实例，通过同一 DOM 外壳改变摆放与可见性。不能用桌面/手机两套 `v-if` 树相互替换阅读器、Agent 或 RP。

| 对象 | 本次保护的现场 |
| --- | --- |
| Markdown | 书籍/内容身份、LID、可用时的段内 UTF-16 位置、相对视口位置 |
| PDF | 来源映射身份、页、页内位置、缩放策略或倍率 |
| 问答 | 会话、当前查看消息及相对位置、跟随末尾状态、未发送草稿、冻结引用 |
| RP | 特定内容版本、实际控件参数与步骤、保存状态、未发送追问 |
| 来源往返 | 原阅读位置、来源所属消息或 RP、原主区域与显示偏好 |

不得把整页 `scrollTop`、聊天数组下标或 DOM 节点引用当作可跨重排的唯一位置身份。恢复有明确降级：精确锚点不可用时提示回到可验证的段落或页面；书籍、来源版本或会话不匹配时失效，不按相似文本猜测。

隐藏区域应停止产生“用户正在阅读这里”的测量与进度事件；重新显示时先恢复有效尺寸及锚点，再恢复采样。Agent 运行保持在外层。RP 隐藏不因保存过一次就允许任意销毁；确需重建时走既有快照保存/恢复，保存失败不得静默丢弃现场。

原生临时选择手柄不保证跨浏览器重排保留；**已经冻结的数据引用必须保留**。重排后可用应用高亮表示冻结范围，不得以错误范围恢复原生选择。

首版承诺同一存活页面中的旋转、切区和后台恢复不丢草稿；刷新或系统回收页面后只承诺恢复后端已持久状态。不将未发送草稿“永不丢失”作为已提供能力。新增浏览器草稿持久化若实施，须另定私有存储范围、清除及失效规则。

**否决**：旋转调用 `goto` 或重发问题；每次打开问答都滚到最新消息；恢复旧 RP 时重放制作和 Reader 副作用；把 `KeepAlive`、`Teleport` 或 iframe 元素身份当作现场必然不丢的证明。

**命门**：“阅读 → 选中 → 提问 → 来源预览 → 原文核对 → 返回”始终关联同一证据与问题。

## 4 视口与交互决策：尊重浏览器原生能力

**决策**：应用使用明确的工作区高度及滚动所有权。动态视口单位处理浏览器工具栏变化；安全区保护可点击操作；视觉视口辅助保证输入和浮层可见，但不把所有高度变化都当成键盘。[W2][W3][W4]

采用 `width=device-width, initial-scale=1, viewport-fit=cover` 时同步实现四边安全区。保持用户缩放能力，不设置 `user-scalable=no` 或限制性最大缩放。顶层 VisualViewport 的大小、偏移与缩放要区分处理；iframe 内不能独立假设自己知道顶层键盘遮挡。[W2]

应用主外壳、正文、问答消息区和浮层明确划分滚动所有权。文档根不承载“目录—正文—问答”串联滚动。Grid/Flex 子项允许收缩，避免通过整页 `overflow-x:hidden` 掩盖真实越界。

选区以 document `selectionchange` 为统一观察入口，配合指针与键盘事件。保留原生长按、手柄拖动与复制，排除输入控件和非当前阅读表面。该事件不冒泡且不携带完整选区，处理器应读取 Selection；不能只把原 `mouseup` 改名。[W5]

用户明确点击“提问/笔记/高亮”时先冻结有效范围，再切换区域或输入焦点。PDF 未解析或歧义选区沿用已有解析闸，不因手机交互升级为精确证据。中文输入法组合过程中不触发发送；主要按钮按项目初始目标提供至少 44×44 CSS px 点击区，不能仅靠 hover 暴露关键操作。

**否决**：只替换 `100vh` 就宣告适配完成；全页阻止触摸默认行为；靠大量 z-index 叠加修复浮层；打开问答必定聚焦输入；以禁止缩放换取固定布局。

**命门**：键盘弹出后仍能看见并操作输入和发送；不会发生选区失效后的错引或错标。

## 5 内容决策：局部适配，不改写原始内容

**决策**：代码、公式、表格和图片在自己的容器内适配。代码保持缩进、可读字号和原始复制内容，提供局部横滚、软换行及展开；长公式和宽表格可以局部滚动或展开，不能撑宽整页。

软换行、行号和语法高亮只改变呈现，不改变规范化正文、LID 或 UTF-16 range。组件适配依据其实际容器，不以整屏宽度推断侧栏内部可读空间。图表展开后保持来源及返回入口。

PDF 容器尺寸变化要使对应渲染显式失效，统一重建画布/文字层并重算投影；采用语义页内锚点恢复，而不是对旧 canvas 只做 CSS 拉伸。渲染需有取消、版本隔离与有界资源预算，不能随着整本书滚动无限保留画布。

“规范化正文重排 ↔ PDF 原版核对”作为后续明确能力，不混入首轮几何修复。其实施必须增加显式阅读表面选择，并同步调整笔记落点、选区和导航。无映射时不伪造精确定位，旋转不能自动替用户改变阅读表面。

**否决**：降低全页字号掩盖宽内容；改写正文以获得换行；默认把所有 PDF 都改成重排正文；为了观感放宽来源/选区校验。

**命门**：显示几何与原始证据身份分离，变化后可准确选择、引用和返回。

## 6 RP 决策：宿主适配、内容适配与有界排练同时存在

**决策**：手机适配是产品能力，不要求用户每次在提示词中声明。宿主提供安全区、可用空间、展开和追问入口；生成内容遵循共同响应式与触控约定；预览宿主实际执行有限的窄容器、低高度及触控场景。

内嵌和展开保持同一内容版本及尽可能相同的浏览上下文。不得因旋转改变 `srcdoc`、创建新内容修订或调用模型重新生成。布局变化可本地重绘，控件和步骤不能重置。

在既有 `PreviewRequest.width` 兼容路径之外增加有界的高度与输入模式合同。旧请求继续沿用原默认环境；新请求的维度必须通过上下界校验。排练结果记录实际环境、布局、关键操作、错误和取消状态，不能仅修改 User-Agent 后宣称通过 iPhone 测试。

排练仍在 Windows/Tauri 或 Linux 的现有独立预览宿主执行，不依赖手机在线。宿主提供稳定的测试环境预设，不把客户端实时尺寸变成新的持久业务真相。关键几何或操作失败时修正候选；若预算耗尽，保留旧版或提供明确的文字降级，不把未通过候选标为已通过。

历史 RP 不自动改写或静默重新生成。旧内容不适配时保留可回读文字、来源和显式修改入口。触控排练不改变 `sandbox="allow-scripts"` 及既有来源/现场编译边界，不增加同源、Tauri、文件系统或 Provider 权限。

**否决**：只检查手机全屏而不检查实际 iframe 尺寸；只保证页面加载、不操作控件；点击脚本代替真实输入回执；为移动端解除 iframe 隔离；每次旋转再生成一个手机版本。

**命门**：参数—结果—版本—来源—追问回执保持关联；预览成功不等于内容语义已被证明正确。

## 7 运行与部署决策：恢复原运行，不绕过入口

**决策**：切区、旋转、隐藏问答或临时断线不取消 Resident 运行。恢复时优先读取原 turn 的快照并接回事件流；终态以既有运行/持久化状态为准。创建请求结果未知时显示未知状态并核对，不自动再次 POST 创建运行。

同源页面、API、PDF 和事件流继续通过现有 Linux/Nginx 入口。手机适配不增加直连内网端口、在 URL 中传认证信息或移除认证的旁路。反向代理是否缓冲事件流、认证是否失效，须通过实际部署入口验证，不由前端假设。

现有 Linux 文档记录 HTTP 入口不提供传输加密，并且实例共享当前书与会话；移动适配不能把这两点描述为已经解决。TLS/可信私网接入与真正多设备隔离是独立工作，不以绕过安全边界作为本次修复手段。依据：`docs/Linux阅读器部署.md:110–118,139`。

**否决**：断线后重发问题；关闭问答等同于停止运行；为了兼容浏览器绕过 Nginx；声称设备侧布局独立就等于会话隔离。

**命门**：不增加重复模型调用、跨书状态误用或认证旁路。

## 8 验收与发布决策

**决策**：采用纯函数/组件测试、浏览器自动化、真实服务和真实 iPhone 四层证据。WebKit 自动化是重要补充，但不是完整 Safari/iPhone 验收的替代。[W6]

发布门槛以连续任务为准，而不是几张互不关联的尺寸截图。必须在同一会话中验证旋转、原生选区、中文键盘、来源往返、PDF 对齐、RP 现场与网络恢复。桌面阅读、笔记、来源、Agent 运行及 RP 原有合同同时回归。

先交付工作区外壳与阅读—追问闭环，再完善 PDF/RP 与运行恢复。部分切片完成可以内部试用，但在完整门槛通过前不能写“移动端适配完成”。具体依赖、失败注入、验收指标、发布与回滚见实施方案。

**命门**：本次文件中没有任何“测试已通过”或“线上已部署”的实施声明；后续状态只能由真实证据更新。

## 9 范围、代价与重审条件

首版范围为 iPhone 浏览器访问 Linux `reader-only`，并保持现有桌面消费能力。非目标：独立 iOS App、PWA 离线包、Service Worker 缓存策略、多用户/多设备会话隔离、预构建与源校对工作台的完整手机化、任意布局编辑器、长期学习模型变更。

接受的代价是：需要从 App/RightRail 中适度提取工作区外壳及局部状态；增加跨组件恢复与异步渲染测试；RP 制作增加有界排练成本。不得借本次改造全量重写 App、另立状态管理框架或修改公共书籍 schema。

以下事实出现时重审：用户长期要求两个以上并行内容区域；可读双区域在主力设备上无法达到；手机网页生命周期导致必须提供明确的未发送草稿持久化；客户端需要独立书籍与会话；RP 任意长内容需要专门的宿主管理与资源淘汰合同。新增能力应另立或修订相应边界，不能静默扩大本 ADR。
