# ADR-0132 Agent 循环预算与交付终态分离

状态：已接受，2026-09-19。关联 ADR-0026、0086、0091、0127。

## §1 循环预算可见性

**决策**：每轮向 Agent 暴露剩余工具循环预算。
**否决**：
- 只在预算耗尽后通知：Agent 无法提前收束，已读够证据仍可能继续扩题。
- 直接提高十二轮上限：延后同一种失败，并增加等待与调用成本。
**命门**：计量单位是一次可调用工具的模型采样；提示同时给出当前轮、总上限和本轮之后的剩余轮数。最后两轮要求围绕原问题收束，已有证据足够时直接回答。
**何时回头**：若运行时改成按工具调用或成本动态分配预算，改为暴露新的权威计量单位。

## §2 交付终态判定

**决策**：仅最终修复失败触发通用失败回答。
**否决**：
- 用 `incomplete && 有诊断` 判失败：初稿诊断也会保留在修复成功的回答上，与最终交付结果不是同一事实。
- 清除所有诊断：会丢失可定位初稿问题与修复结果的服务端证据。
**命门**：运行未完成继续表示循环上限或无进展；交付失败只由最终 repair 仍有问题判定。修复成功时保留答案、warning 与服务端诊断。
**何时回头**：若交付器新增显式终态字段，以该字段替代从 repair issues 推导。

## §3 验证边界

**决策**：保持十二轮上限，以失败形状做回归。
**否决**：
- 同时重写进度守卫：本次证据只证明预算不可见与终态混淆，尚未证明守卫算法需要替换。
**命门**：测试覆盖修复成功但恰逢上限、修复失败仍降级，以及连续两轮预算数字和耗尽后的禁用工具终答。
**何时回头**：若真实轨迹在预算可见后仍稳定扩题，再单独调整相关性/进度判定。
