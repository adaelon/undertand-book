# 一键预构建执行面与成本治理修复方案

状态:已完成,AP0-AP16 已于 2026-07-19 通过实现、隔离真书回放、打包与插件安装门禁。

依据:

- [2026-07-18 Understanding Transformer 预构建运行统计](./运行统计-2026-07-18-understanding-transformer预构建.md)
- [ADR-0084 Codex harness inference and durable sidecar task mailbox](./adr/0084-codex-harness-inference-and-durable-sidecar-task-mailbox.md)
- [ADR-0085 Stage-specific work units and policy-bound artifacts](./adr/0085-stage-specific-work-units-and-policy-bound-artifacts.md)

## 1. 目标与边界

本方案修复一键预构建的执行所有权、任务身份、并发恢复、成本控制与质量可追溯性。目标不是减少一切 LLM 调用,而是让每次调用有必要、有界、可续跑、可审计,且不因执行压力改变语义质量。

必须保持的边界:

| 边界 | 约束 |
| --- | --- |
| 模型执行 | Codex harness 与专用 subagent 执行语义模型;Build Engine Sidecar 不直连 provider |
| 构建真相 | `.build/<stage>` 的已验证 artifact 仍是 stage 真相;job/task 自述不能替代 |
| 来源真相 | Paper 只消费 Workbench 已可信 `source.txt/base.json/source_manifest.json`;不得重写 LID/source truth |
| 判定权 | schema/hash/evidence/quality floor 由确定性代码判定;LLM 只产候选 |
| Token 口径 | 仅原生 usage receipt 可记精确 Token;无 receipt 时记 `unknown`,估算字段单列 |
| 兼容 | 既有 v1 中间产物不自动删除、覆盖或伪装成 v2 policy-compatible artifact |

非目标:

- 不在 sidecar 内新增 OpenAI/Anthropic/Ollama 客户端或凭据管理。
- 不建设分布式队列、多用户调度或云端 artifact store。
- 不改变 Reader 的 LID、citation、PDF projection 或 source trust 契约。
- 不用低质量模板、空输出或默认 reject-all 换取 stage 完成。
- 不承诺外部 provider、Agent slot 或沙箱调度的绝对墙钟时间。

## 2. 已证实基线

Understanding Transformer 样本不是单纯的工具延迟事故。当前数据同时暴露了执行边界和任务建模问题:

| 证据 | 实测 | 说明 |
| --- | ---: | --- |
| 叶 LID | 2,075 | 坐标粒度远细于论文语篇粒度 |
| formula 叶 LID | 867 | 41.8% 叶子为公式或行内公式碎片 |
| Pass1 窗口 | 48 | 后续三个 stage 无条件复用 |
| 平均窗口 token | 847 | 仅使用 12,000 输入预算的 7.1% |
| 最小窗口 | 1 LID / 3 token | 仍触发完整 extractor/writer 流程 |
| metadata 空产物 | 44/48 | 91.7% 调用没有业务字段 |
| 已完成 sidecar discourse | 1,450 | 与对应窗口全部叶 LID 数完全相等 |
| Pass1 叶锚定率 | 916/2,075 = 44.14% | 当前 close 只报告,不执行质量 floor |
| 最少语义输出 | 177 | 不含纯重传与未来 Pass2/BookStructure |

根因到方案的映射:

| 根因 | 目标机制 |
| --- | --- |
| 完整 JSON 经 subagent -> root -> patch | executor-owned candidate + receipt-only root handoff |
| builder 只出计划,无 durable 执行状态 | per-work-unit task mailbox + lease/heartbeat/recovery |
| `record-attempt` 错 target | canonical workspace target reference |
| 共享 `attempts.json` 并发丢更新 | per-attempt 独立目录与幂等事件 |
| Pass1 窗口泄漏到所有 stage | stage-specific work-unit router |
| OCR/LID 粒度决定语义输出 | paragraph/formula/context 等 stage 语义单元 |
| source-only content hash | policy-bound artifact fingerprint |
| 中途压缩质量仍算 fresh | stage quality profile 冻结 + policy drift 阻断 |
| 无 Token/延迟事实 | task receipt + 可选 usage receipt + 确定性耗时 |
| prompt 与 writer schema 不对称 | 单一 schema 源生成 prompt contract 与 writer validator |

## 3. 目标执行链

```text
root invokes plan/next
  -> Build Engine Sidecar recomputes stage readiness
  -> stage router emits costed WorkUnitDescriptor[]
  -> sidecar atomically claims affordable units and writes TaskLease
  -> root starts one specialized subagent per lease
      -> subagent reads prompt + input through lease commands
      -> subagent writes candidate into its task-owned mailbox
      -> subagent calls task submit with optional usage receipt
  -> sidecar validates candidate against lease identity
      -> deterministic writer/gate commits stage artifact
      -> task receipt records hashes,counts,timing,diagnostics
  -> subagent returns receipt summary only
  -> root requests next batch
  -> close_stage recomputes completeness + selected quality policy
  -> done | needs_user | failed
```

Root 上下文只允许出现以下数据:

```ts
interface RootTaskReceipt {
  task_ref: string;
  state: "committed" | "retryable_failure" | "needs_user";
  artifact_sha256?: string;
  output_counts?: Record<string, number>;
  diagnostic_code?: string;
  usage_status: "reported" | "unknown";
}
```

完整候选 JSON、完整输入窗口和 writer 产物不得进入 root 正常返回。调试时读取完整 payload 必须是用户或维护者的显式动作。

## 4. 组件职责

| 组件 | 拥有 | 不拥有 |
| --- | --- | --- |
| Codex root | 一命令 loop、可用 Agent slot、用户交互、receipt 汇总 | 完整候选传输、任务完成真相、尝试次数 |
| 专用 subagent | 单一 lease 的语义推理、candidate、可选 usage receipt | stage 选择、其他任务历史、最终 artifact 判定 |
| Build Engine Sidecar | target 解析、work-unit 规划、租约、mailbox、writer/gate、指标聚合 | 模型推理、provider 凭据、语义自评 |
| Core stage router | stage-specific work unit、input hash、cost、skip reason | 调度、模型执行、磁盘任务状态 |
| Stage writer | schema/evidence/policy identity 校验、原子 artifact commit | 重试策略、质量档位变更 |
| Stage close gate | completeness、quality floor、公共 artifact 原子发布 | 以 job/receipt 数量替代 artifact 回读 |

## 5. Durable work-unit contract

### 5.1 Work unit

```ts
type SemanticStage =
  | "pass1"
  | "paper_metadata"
  | "paper_lexicon"
  | "profile_sidecar_discourse"
  | "profile_sidecar_formula"
  | "pass2"
  | "book_structure_unit"
  | "book_structure_stitch";

interface WorkUnitDescriptorV2 {
  version: "automatic_build_work_unit.v2";
  target: BuildTargetRefV2;
  stage: SemanticStage;
  work_unit_id: string;
  kind:
    | "pass1_window"
    | "metadata_region"
    | "lexicon_candidate_batch"
    | "discourse_paragraph_group"
    | "formula_context_group"
    | "pass2_candidate_batch"
    | "structure_unit"
    | "structure_stitch";
  dependencies: Array<{ artifact: string; sha256: string }>;
  input_hash: string;
  policy_fingerprint: ExtractionPolicyFingerprintV1;
  evidence_lids: string[];
  cost: WorkUnitCostV1;
  deterministic_skip?: { code: string; evidence: string[] };
}

interface WorkUnitCostV1 {
  estimated_input_tokens: number;
  visible_lids: number;
  formula_lids: number;
  table_fragments: number;
  candidate_count: number;
  expected_output_items: number;
  score: number;
}
```

`deterministic_skip` 是可审计完成态,不是伪造的空 LLM artifact。Stage close 必须区分 `committed`、`skipped`、`pending` 与 `failed`。

AP9-AP15 期间 automatic stage state 以 `work_units/pending_work_units` 为新真相,并保留 `pending_tasks/task_bindings` 作为 AP16 前兼容投影。非 Pass1 router 在 AP10-AP12 完成前只包装既有窗口;其中 `profile_sidecar_window_v1` 是明确的迁移 kind,不得被解释为最终 discourse/formula 语义单元。

### 5.2 Target identity

```ts
interface BuildTargetRefV2 {
  version: "build_target_ref.v2";
  workspace_dir: string;
  book_id: string;
  profile_id: string;
  input_fingerprint: string;
}
```

所有 `claim/submit/fail/reset/close` 命令接收 `BuildTargetRefV2` 或其持久化路径。不得再次用 `source.txt` 猜 workspace。

解析规则:

1. 显式 workspace 规范化后读取 manifest 与 `base.json` identity。
2. 原始输入文件只允许通过 manifest 的 `original_path` 或 input hash 唯一匹配。
3. 位于 `.understand-book/<book_id>/source.txt` 的路径必须解析为其包含 workspace,并复验 manifest/base identity。
4. 无法证明 paper workspace identity 时 fail-closed;不得降级为 `technical_learning/book_id=source`。
5. 每条 task/receipt 同时记录 workspace、book、profile 与 fingerprint,任一不一致即拒绝。

### 5.3 Task mailbox

```text
.build/automatic-build/v2/
  plan.json
  tasks/<stage>/<work_unit_id>/
    descriptor.json
    attempts/0001/
      lease.json
      heartbeat.json
      candidate.json
      usage-receipt.json        # optional
      validation.json
      receipt.json
      failure.json
```

Task 状态机:

```text
pending
  -> leased
      -> submitted
          -> validating
              -> committed
              -> retryable_failure -> pending(next attempt)
              -> needs_user
      -> lease_expired -> pending(next attempt)
```

约束:

- Claim 使用原子目录创建或等价的 create-new 语义;同一 work unit 同时只能有一个有效 lease。
- Lease 带 owner、attempt、issued_at、expires_at、policy/input hash 与随机 token。
- Submit 必须匹配 lease token、input hash 与 policy fingerprint;重复 submit 返回同一 receipt。
- Heartbeat 只覆盖本 attempt 的独立文件,不写共享 ledger。
- 每次 attempt 写独立目录;失败和成功都不删除历史证据。
- Stage summary 由目录聚合生成,不得作为任务状态的唯一来源。

### 5.4 Candidate handoff

专用 subagent 不再“只返回 JSON”。新契约是:

```text
read task contract -> execute prompt/input -> write task-owned candidate
-> submit candidate -> return receipt only
```

Sidecar 提供以下命令面:

```text
plan <target-ref> [--quality <profile>] [--budget <file>]
claim <target-ref> [--max-cost N] [--max-tasks N] [--owner ID]
task input <lease-path>
task submit <lease-path> <candidate-path> [--usage-receipt <path>]
task fail <lease-path> --diagnostic <path-or-code>
task heartbeat <lease-path>
task inspect <task-ref>
close <target-ref> <stage>
```

`task submit` 是受控 artifact API,不是任意文件写入口。Candidate path 必须位于当前 attempt mailbox,并通过路径边界、大小、JSON、schema、identity 与 evidence gate。

## 6. Policy-bound artifact identity

```ts
interface ExtractionPolicyFingerprintV1 {
  profile_id: string;
  profile_version: string;
  stage_policy_version: string;
  router_version: string;
  prompt_sha256: string;
  schema_version: string;
  quality_profile: "full" | "balanced" | "sparse";
}

interface SemanticArtifactEnvelopeV2<T> {
  version: "semantic_task_artifact.v2";
  target: BuildTargetRefV2;
  stage: SemanticStage;
  work_unit_id: string;
  input_hash: string;
  policy_fingerprint: ExtractionPolicyFingerprintV1;
  artifact_hash: string;
  provenance: {
    executor: string;
    model?: string;
    attempt: number;
    generated_at: string;
  };
  payload: T;
}
```

Freshness 由 `target fingerprint + input_hash + policy_fingerprint` 决定。具体 provider/model 写入 provenance;只有允许模型范围改变时才提升 `stage_policy_version`,避免无意义地因 provider 切换全量失效。

AP7-AP15 迁移期采用双轨读取:automatic v2 snapshot 只把完整 envelope 且 policy 匹配的任务判 fresh;既有直接 writer/status/batch 仍可解包或读取 legacy v1 payload,但 legacy v1 明确为 `policy_fresh=false`。默认切换与旧工件迁移只在 AP16 发布门禁后发生。

质量档位在 stage 第一次 claim 前冻结:

- `full`:最高召回与解释覆盖,允许更高预算。
- `balanced`:保持核心覆盖,减少低价值候选。
- `sparse`:只保留强证据任务,但仍满足该档位明确的 quality floor。

运行中不得把 `full` 临时改成 `sparse`。需要改变时创建新 policy fingerprint,旧 stage 进入 `policy_mismatch`,由用户选择重建或恢复原策略。

## 7. Stage-specific work units

| Stage | 工作单元 | 确定性预路由 | 完成判据 |
| --- | --- | --- | --- |
| Pass1 | ADR-0009 LID subtree window | 保留现有窗口;按预期节点/公式/表格成本调度 | 每个 fresh 窗口 committed/skipped;graph gate 与质量 floor 通过 |
| Paper metadata | front matter、bibliography、identifier、dataset/code/funding 区域 | 无字段信号的区域 skipped;结构化 references 可确定性解析 | 所有候选区域 accounted;字段 envelope/evidence 合法 |
| Paper lexicon | 术语候选簇与 occurrence batch | 规范化候选、缩写/方法/数据集信号;普通词 skipped | 候选簇 accounted;occurrence/definition evidence 合法 |
| Sidecar discourse | 连续叙述 paragraph group | formula/image/table fragment 不自动成为 discourse item | eligible paragraph group accounted;标签与关系通过 policy floor |
| Sidecar formula | formula LID + 邻接解释上下文 | 裸变量、页码、脚注号、无解释邻接的碎片 skipped | grounded candidate accounted;参数/组合 evidence 合法 |
| Pass2 | candidate-bearing packet | 无 candidate 的窗口 skipped | 每个 candidate accepted/rejected/pending 有审计 |
| BookStructure | structure unit + stitch | 沿用当前 unit/stitch 边界 | 全 unit fresh,stitch evidence/reference gate 通过 |
| ReadingGuide | 确定性 projection close | 无 LLM work unit | 输入 hash 与 projection verification 通过 |

关键区分:

- LID 是证据坐标,不等于 discourse item。
- Formula LID 可以独立做公式证据,不强制拥有段落功能标签。
- Metadata 是文档级事实,不得因 Pass1 有 48 窗就自动产生 48 次模型调用。
- Skip 必须有 router 版本、原因码和输入证据,保证未来规则升级可使其重新 pending。

成本调度不再使用固定“5 tasks”作为唯一上限:

```text
score = estimated_input_tokens
      + 40 * expected_output_items
      + 80 * formula_lids
      + 60 * table_fragments
      + 30 * candidate_count
```

数值由真书 benchmark 校准并版本化。Scheduler 同时限制 `max_tasks`、`max_total_score` 与可用 Agent slot;单个高成本 work unit 不与其他高成本单元强行同批。

## 8. Prompt/schema 单一契约

Extractor prompt、writer validator 与测试 fixture 必须消费同一 schema 源。每个 stage contract 包含:

```ts
interface ExtractorContractV1 {
  stage: SemanticStage;
  schema_version: string;
  json_schema: object;
  cross_field_invariants: string[];
  allowed_evidence_lids: string[];
  max_output_bytes: number;
}
```

规则:

1. Prompt 展示完整字段 shape,包括 `references.value: Array<{raw,identifiers?}>` 等嵌套结构。
2. `defined_at_lid in occurrences_lids` 等关系不变量由 schema companion 明示。
3. Writer 返回稳定错误码、JSON pointer、expected/actual 与 evidence violation。
4. 自动重试使用相同 policy fingerprint,只附加确定性诊断。
5. 输出超限时拆 work unit 或进入 `needs_user`;不得临时要求“更 sparse”后继续沿用旧 hash。
6. Prompt/schema/policy 任一变化都通过 fingerprint 使旧 artifact 显式 stale。

## 9. 遥测与预算门禁

### 9.1 Task metrics

```ts
interface TaskMetricsV1 {
  version: "automatic_build_task_metrics.v1";
  task_ref: string;
  stage: SemanticStage;
  work_unit_id: string;
  attempt: number;
  queue_ms: number;
  lease_wait_ms: number;
  executor_ms?: number;
  writer_ms: number;
  input_bytes: number;
  output_bytes: number;
  output_items?: number;
  status: "committed" | "skipped" | "retryable_failure" | "needs_user";
  diagnostic_code?: string;
  usage: {
    source: "native" | "executor_reported" | "unavailable";
    model?: string;
    input_tokens?: number;
    cached_input_tokens?: number;
    output_tokens?: number;
  };
  estimate?: {
    method: string;
    input_tokens: number;
    output_tokens: number;
  };
}
```

精确 usage 与 estimate 永远分栏。`source=unavailable` 时精确字段必须缺省,UI/CLI 显示“未知”,不得回填估算值。

当前 v1 planner 在同一次 `next` 中发现并立即 claim work unit,因此没有独立持久队列等待期,`queue_ms=0`;`lease_wait_ms` 从 lease 发出到 executor 开始 input 计算。AP9 若引入独立 ready/queued 时间,再以新事实替换该口径,不得从 wall clock 或 bytes 反推。

Metrics 按 attempt 独立落盘。Stage close 单线程生成可重算 summary:

- work unit 总数、skipped/committed/retry 数。
- 精确 Token 已知覆盖率及已知总量。
- estimated Token 区间及估算方法。
- queue/executor/writer 的 P50/P95。
- 空输出率、平均输出 bytes、schema failure 分布。
- 每 1,000 eligible LID / candidate 的成本。

### 9.2 Preflight plan

首次 claim 前输出:

```text
stage/work-unit counts
eligible/skip counts
cost score distribution
estimated input/output token range + confidence
historical P50/P95 when available
selected quality profile + policy hash
available worker slots
```

预算文件支持:

```ts
interface AutomaticBuildBudgetV1 {
  max_model_tasks?: number;
  max_estimated_tokens?: number;
  max_wall_clock_minutes?: number;
  max_output_bytes?: number;
  max_parallel_cost?: number;
  on_exceed: "needs_user" | "stop";
}
```

无历史数据时必须标低置信区间。预算超过阈值先进入 `needs_user`;不得运行数小时后才暴露成本。

## 10. 完整性与质量门禁

完整性与质量分开:

```text
integrity failed -> failed,不发布
integrity passed + quality below selected floor -> needs_user,不宣称 done
integrity passed + quality meets selected floor -> completed(<quality_profile>)
```

| Stage | Integrity | Quality |
| --- | --- | --- |
| Pass1 | work-unit/accounting、hash、LID、graph schema/edge gate | eligible semantic unit anchor rate、drop ratio、goldset precision/recall |
| Metadata | candidate region accounting、MetadataField/evidence | front matter/reference/identifier candidate coverage |
| Lexicon | candidate accounting、term/evidence schema | duplicate rate、defined evidence、goldset term coverage |
| Discourse | eligible paragraph accounting、enum/LID | grounded summary/function coverage、低信息 filler rate |
| Formula | candidate accounting、context/evidence | grounded formula coverage、invalid/bare-fragment skip precision |
| Pass2 | candidate disposition 完整 | accepted edge precision、pending rate |
| Structure | unit/stitch/reference 完整 | throughline/key-stop evidence coverage |

Pass1 的旧 `all leaf LID anchor rate` 继续保留为诊断,但不直接作为质量 floor。Quality denominator 必须由版本化 router 定义的 `eligible semantic units` 给出,避免把 `$t$`、页码或分隔符当成必须生成 graph node 的对象。

所有质量阈值由许可 fixture + 哈希绑定真实论文 benchmark 校准。LLM 自评不能作为发布门。

## 11. 并发、失败与恢复

| 场景 | 确定性行为 |
| --- | --- |
| Agent slot 少于计划 | 只 claim 可启动数量;未 claim 单元保持 pending |
| 无专用 subagent | `needs_user(executor_unavailable)`;不复用通用 root 伪造输出 |
| Root 会话中断 | lease 到期后重新 pending;candidate/receipt 已提交则幂等复用 |
| Sidecar/机器中断 | 扫描 task directories;按 lease TTL 与 receipt 恢复 |
| Provider 失败 | 写 attempt failure;未到上限则新 attempt,不覆盖旧诊断 |
| Schema/evidence 失败 | 返回稳定诊断给同一 work unit;最多三次 |
| Source/policy 变化 | 未提交 lease 作废;旧 artifact 标 stale,不得跨 fingerprint submit |
| 重复 submit | 返回已存在 receipt;不得重复 writer commit |
| 并发 claim | 原子 claim 保证一个有效 owner;不依赖共享 JSON RMW |
| usage 缺失 | artifact 可提交;metrics 标 `unavailable`,不伪造 Token |

默认并发不是固定 5。Planner 根据 Agent slot 和 cost budget 决定 1-3 个 worker;只有真书 benchmark 证明更高并发不会恶化错误率、上下文和系统延迟时才提高。

## 12. Legacy 迁移

### 12.1 兼容原则

- v1 `.build/<stage>/<id>.json` 保持原位且只读,不自动打上 v2 policy fingerprint。
- v2 task/mailbox 使用独立 namespace;候选全部验证后才原子发布公共 artifact。
- 同一 stage 不允许混合 v1 source-only hash 与 v2 policy-bound hash 后宣称 v2 complete。
- 提供 `audit-legacy` 命令,输出 source freshness、schema、覆盖、已知 prompt/policy 缺口和建议动作。

迁移选择:

```text
legacy_resume
  -> 只允许使用冻结的 legacy contract 完成原 stage
  -> 结果标 legacy_policy_unknown
  -> 不宣称 v2 reproducible

v2_rebuild
  -> 保留旧目录作为审计/回滚
  -> 生成 v2 work units
  -> 全部 gate 通过后原子替换公共 artifact
```

### 12.2 Understanding Transformer 样本

建议迁移顺序:

1. 保留 Workbench source reconciliation 与 HF2 v2 foundation,不重建来源真相。
2. 保留现有 Pass1、metadata、lexicon v1 artifact 作为 legacy 对照。
3. `profile_sidecar` 已发生同 stage 质量策略漂移,不应继续混入 v2;新执行面完成后优先整 stage v2 rebuild。
4. 新 quality gate 评估 Pass1 的 eligible-unit coverage;未过线再决定只重建受影响 Pass1 units,不因旧 44.14% 全叶锚定率直接全量删除。
5. Pass2、BookStructure 与 ReadingGuide 只消费同一 policy generation 已正式关闭的上游 artifact。

任何迁移都不得清理根目录临时 JSON、用户输入或旧 artifact,除非 retention policy 已实现并由用户显式执行。

## 13. 验收矩阵

| 能力 | 确定性验收 |
| --- | --- |
| Target identity | 对 reconciled `source.txt` 执行任何 task 命令仍解析到原 paper workspace;绝不创建 `.understand-book/source` |
| Attempt 并发 | 3 worker 并发 claim/fail/success 无丢记录、重复 owner 或共享文件覆盖 |
| Artifact handoff | Root trace 不含 candidate JSON;每个 task 只返回小型 receipt |
| Crash recovery | 在 claim、candidate write、validation、commit 各故障点恢复后只有 pending 或完整 committed |
| Stage routing | 样本 metadata 模型任务相对 48 次至少减少 80%,所有 deterministic skip 有 receipt |
| Sidecar units | Formula/脚注碎片不再强制产生 discourse item;paragraph/formula accounting 均完整 |
| Policy freshness | prompt/schema/quality profile 任一变化使旧 artifact stale;model provenance 仍保留 |
| Quality freeze | Stage 中途修改 quality profile 被拒绝,不会复用旧 content hash |
| Prompt/schema | metadata references 与 lexicon definition invariants 无需猜测;fixture 首次通过 writer |
| Telemetry | queue/writer/input/output bytes 总是存在;Token 缺失明确为 unknown |
| Budget gate | 超过用户阈值时首批模型调用前进入 needs_user |
| Legacy | v1 artifact 未被自动覆盖;legacy_resume 与 v2_rebuild 状态不可混淆 |
| Packaging | Node/tsx 与编译 sidecar 输出同一 task protocol;Windows smoke 使用真实 exe |
| 真书发布 | 隔离副本两次构建得到相同 policy/artifact digest,无错误 workspace、无 root JSON relay |

性能验收优先比较模型任务数、root 传输 bytes、writer P95 和 cost-normalized throughput。外部 provider 墙钟只作观测,不作为唯一发布判据。

## 14. 风险与回头条件

- **Router 漏召回**:确定性预路由可能跳过真实语义。先以 full profile 运行许可/真实 goldset,skip precision 未达标不得启用生产跳过。
- **Mailbox 复杂度**:任务状态比 ADR-0042 更重。真实并发、错误 target 和跨会话审计已使“无状态位”前提失效;实现仍限制在单机目录协议。
- **Agent 能力差异**:部分 harness 不能返回 usage 或直接写 task path。协议允许 usage unknown,但不允许退回 root JSON relay 作为默认路径。
- **质量阈值误设**:阈值必须版本化并用真书校准,不得为 Understanding Transformer 单样本调参。
- **旧书迁移成本**:默认读旧 artifact,只有用户选择 v2 rebuild 才消耗模型预算。

回头条件:

- Codex 提供稳定的原生 task/executor API 时,可以用 adapter 替换 skill 驱动层,mailbox 与 artifact gate 保持不变。
- Build Engine Sidecar 未来被明确授权托管模型时,新增 provider adapter ADR,不得在本方案内暗改边界。
- Stage-specific router 在多书 benchmark 上未能同时降低任务数并保持质量时,回退该 stage router,不回退 mailbox、identity 与 telemetry。
