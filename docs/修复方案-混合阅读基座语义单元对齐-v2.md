# 修复方案:混合阅读基座语义单元对齐 v2

状态:Accepted,2026-07-17。实现状态:HF2-0 至 HF2-7 全部完成,2026-07-18。变更类型:`[边界重构]`。

本方案修复 `hybrid foundation text mapping coverage is below the reader-ready minimum`,取代旧 PH5 中按细碎 SourceBlock 对齐、用覆盖率阻断 Reader 的部分。来源真相仍遵守 ADR-0063/0065,页内顺序与保守重同步仍遵守 ADR-0079,新边界由 ADR-0082 定义。

## 1. 对齐确认单

**FrozenIntent**:让已完成来源复核的论文在 PDF 映射完整性安全时进入 Reader;同时改进公式密集论文的对齐算法,按真实投影精度限制引用、复制和标注。算法、artifact 协议、迁移和 UI 同版交付。

**不做**:不改变 LID/SourceBlock 分区,不增加 OCR/扫描件支持,不让人工决定或 LLM 认证 bbox,不在本方案新增“复制矫正后格式”命令,不覆盖真实论文的现有正式产物做试验。

**成功标准**:第 9 节整版发布门全部通过;当前公式密集论文至少以 `degraded` 进入 Reader,可比覆盖指标严格改善,错误页与重复绑定为零,危险操作始终 fail-closed。

**TermMap**:Hybrid alignment unit、Source alignment evidence、PDF projection precision、Hybrid foundation integrity gate、PDF alignment quality tier、Versioned alignment benchmark 均已定义于 `CONTEXT.md`,零未解析术语。

**RiskReceipt**:用户已确认人工来源复核不证明 PDF 几何,并选择扩大单版变更面以换取完整的能力门禁与迁移闭环。

## 2. 故障基线

权威失败发生于 2026-07-17T11:07:45.688Z:

```text
workspace: .understand-book/understanding-transformer-from-the-perspective-of
job:       .build/jobs/job_e178df663fecebb9.json
run:       run_fa8c395a5754
error:     hybrid foundation text mapping coverage is below the reader-ready minimum
```

对同一输入只读重算得到:

| 输入 | 可对齐正文 | 已映射 | 正文覆盖率 | 标题覆盖率 |
| --- | ---: | ---: | ---: | ---: |
| 原始 Markdown | 1118 | 550 | 49.19% | 未作为终裁基线 |
| 人工复核后来源 | 1100 | 559 | 50.818% | 38/43 = 88.37% |

人工复核后共有 2077 个叶 LID,559 个映射、1518 个未映射,PDF 46 页。复核让正文覆盖率略有改善,不是失败原因。

粒度分布解释了当前算法的结构性上限:

- 1100 个正文块中,328 个只有 1-3 token,485 个为 4-15 token,只有 287 个达到 16 token 首锚长度;73.9% 低于正常段落锚。
- Markdown adapter 将行内公式拆成独立 formula leaf;该论文形成 868 个公式 asset leaf,其中 154 个为展示公式;另有 19 张图片和 2 个 HTML 表格。
- 当前 `matchBlockToPdfLines` 对所有 `assetKind` 直接返回 `unmapped`;少于 4 token 的非标题块又要求 exact。
- 当前 60% 正文、80% 标题阈值同时位于 `hard_gates`,覆盖率不足会阻止任何安全降级结果写入。

## 3. 根因与责任边界

1. **粒度错配**:`source_reconciliation` 以“正文 + 公式上下文”比较,`hybrid-foundation` 却重新按更细 SourceBlock 首锚定位;用户复核的语义单元没有传递到下游。
2. **证据丢失**:来源对齐已经知道页、候选文本和等价状态,但下游只收到 `source.txt`;人工项与确定性项都被迫从零搜索。
3. **公式天然失配**:公式 leaf 被无条件排除,其两侧短正文又缺少稳定锚,一个公式会制造多个未映射子项。
4. **门禁分类错误**:指纹、哈希、页边界属于完整性;覆盖率属于质量。把二者放入同一 hard gate 会把“少但安全”误判成“artifact 不可信”。
5. **能力表达过粗**:`word_mapped | line_fallback | block_fallback | unmapped` 不能直接回答某个选区能否安全引用、复制或持久化。

Canvas/PDF.js 警告不属于本故障。PDF 几何抽取已覆盖全部 46 页。

## 4. 目标状态机与能力矩阵

```text
SOURCE_UNTRUSTED
  -> Build Workbench

SOURCE_TRUSTED
  -> BUILD_V2_CANDIDATE
      -> integrity failed: STAGE_FAILED -> keep official artifacts unchanged
      -> integrity passed:
           quality full     -> STAGE_COMPLETED(full)     -> Reader
           quality degraded -> STAGE_COMPLETED(degraded) -> Reader
```

`stage_completed` 表示 artifact 安全且可消费,不表示每个 LID 都已精确映射。Reader 全局显示非阻塞的“PDF 对齐:部分可用”,并允许打开 Workbench 对齐诊断。

| 投影精度 | 导航/对象标记 | 字符引用与 Ask AI range | Highlight/Note | 语义矫正版复制 | PDF 原生选择/复制 |
| --- | --- | --- | --- | --- | --- |
| `char_exact` | 允许 | 允许 | 允许 | 可作为前置条件,本方案不新增命令 | 允许 |
| `region_exact` | 允许 | 禁止 | 禁止 | 禁止 | 允许 |
| `partial` | 只导航已证实区域 | 仅返回 exact 子区间并显式警告 | 整体禁止 | 禁止 | 允许 |
| `unmapped` | 无语义导航 | 禁止 | 禁止 | 禁止 | 允许 |

全局 `degraded` 不直接禁用所有操作;每次选择或投影请求都按涉及的最低精度决定能力。

## 5. v2 Artifact 契约

### 5.1 来源证据

Source reconciliation 在接受最终 `source.txt` 时写 `.build/source-reconciliation/alignment-evidence.json`:

```ts
interface HybridAlignmentInputFingerprint {
  source_sha256: string;
  pdf_sha256: string;
  reconciliation_config_hash: string;
  evidence_policy_version: "source_alignment_evidence_policy.v1";
}

type SourceEvidenceStatus =
  | "verified"
  | "format_equivalent"
  | "reviewed_hint"
  | "unmapped";

interface AlignmentUnitEvidence {
  unit_id: string;
  source_span: { start: number; end: number };
  pdf_line_spans: Array<{
    pageIndex: number;
    start_line_index: number;
    end_line_index: number;
  }>;
  status: SourceEvidenceStatus;
}

interface SourceAlignmentEvidenceV1 {
  version: "source_alignment_evidence.v1";
  book_id: string;
  input_fingerprint: HybridAlignmentInputFingerprint;
  units: AlignmentUnitEvidence[];
}
```

规则:

- `verified`/`format_equivalent` 可提供局部定位种子,但 v2 aligner 仍校验 source/PDF 指纹、单调顺序与候选内容。
- `reviewed_hint` 只缩小页/行搜索窗口;它不能直接产生 `char_exact` 或 `region_exact`。
- 指纹不一致时整份 evidence 为 stale,不能部分复用。
- evidence source span 必须基于最终 accepted/manual-override `source.txt`,不能沿用 review draft 的旧偏移。

### 5.2 对齐单元与子投影

```ts
interface HybridAlignmentUnit {
  unit_id: string;
  source_span: { start: number; end: number };
  child_lids: Array<{
    lid: string;
    source_span: { start: number; end: number };
    kind: "text" | "formula" | "image" | "table" | "code";
  }>;
}

type PdfProjectionPrecision =
  | "char_exact"
  | "region_exact"
  | "partial"
  | "unmapped";

interface PdfSourceMapEntryV2 {
  lid: string;
  source_span: { start: number; end: number };
  precision: PdfProjectionPrecision;
  regions: PdfRegion[];
  exact_source_spans: Array<{ start: number; end: number }>;
  primary_region?: PdfRegion;
  alignment: { unit_id: string; reason: string; trace_id?: string };
}
```

`pdf_source_map.v2` 每个叶 LID 恰有一个 entry。`pdf_selection_map.v2` 只给 `char_exact` 字符写规范 LID/source span;`region_exact` 只存在于 source map。

公式只有在两个可信字符锚之间形成同页、同栏、单调且唯一的几何空隙时才能成为 `region_exact`;否则为 `partial` 或 `unmapped`。该规则不允许推导字符范围。

### 5.3 完整性与质量

`alignment_report.v2` 将二元门禁与质量指标分开:

```ts
interface HybridFoundationIntegrityV2 {
  input_fingerprint_matches: boolean;
  artifact_hashes_match: boolean;
  all_leaf_lids_unique_and_present: boolean;
  all_regions_in_page_bounds: boolean;
  located_units_monotonic: boolean;
  no_duplicate_pdf_bindings: boolean;
  selection_shards_match_manifest: boolean;
}

interface HybridFoundationQualityV1 {
  policy_version: "hybrid_quality_policy.v1";
  tier: "full" | "degraded";
  unit_location_ratio: number;
  exact_text_span_ratio: number;
  exact_formula_ratio: number;
  heading_location_ratio: number;
}
```

`exact_text_span_ratio` 按 canonical source span 长度加权,避免大量短片段扭曲指标。`quality_policy.v1` 的数值只由第 7 节基准校准后提交,不得为当前论文临时调参。

本方案中的 v1/v2 指 `pdf_source_map`、`pdf_selection_map` 和 `alignment_report`。`source_manifest.v2` 保持现有版本,增加可选的 `alignment_quality` 块并继续使用现有 capability envelope;旧消费者可忽略新增字段。

## 6. 确定性算法

```text
units = form_alignment_units(final_source_blocks)
evidence = load_if_fingerprint_matches(source_alignment_evidence)
cursor = PDF_START

for unit in units:
  seed = verified_or_equivalent_seed(unit, evidence)
      ?? reviewed_search_hint(unit, evidence)
      ?? cursor_window(cursor)

  located = locate_unique_monotonic_unit(unit, seed)
  if not located:
    emit every child as unmapped
    continue

  projections = project_children_within_lines(unit.children, located.lines)
  for child in projections:
    emit char_exact only for deterministic source-char assignments
    emit region_exact only for a unique bounded formula/object gap
    otherwise emit partial or unmapped

  cursor = end of located unit

integrity = validate_fingerprint_hash_schema_order_bounds_uniqueness()
if integrity failed:
  reject candidate
else:
  quality = score_with_versioned_policy()
  stage candidate for atomic replacement
```

禁止项:

- 不得把 fuzzy similarity、LLM 判断或人工 `accept_markdown` 直接提升为 exact 几何。
- 不得让短片段单独执行全局 contains 搜索。
- 不得用父单元 bbox 填充未投影子 LID。
- 不得因一个子 LID 失败而回退或复用前一子项的 PDF 字符。
- 不得以提高覆盖率为理由放宽 ADR-0079 的唯一、单调、页距约束。

## 7. Versioned alignment benchmark

基准目录:

```text
packages/core/test/fixtures/hybrid-foundation-goldset/
  v1/
    manifest.json
    licensed-inline-formula/
      source.md
      paper.pdf
      expected.json
    licensed-two-column-formula/
      source.md
      paper.pdf
      expected.json
    external-formula-dense-transformer.json
```

`expected.json` 冻结 source span 到 page/line/bbox/precision 的人工真值。可生成或许可的小 PDF 入库;真实 Transformer 论文只提交输入哈希、样本 span 标识和预期页/行,运行时显式提供本地 `.understand-book` 路径,不得提交受版权保护的正文/PDF。

确定性 runner 输出:

- annotated wrong-page count;
- duplicate PDF binding count;
- integrity gate matrix;
- 四个质量指标与 policy version;
- v1/v2 可比的 source-span coverage delta;
- 同输入重复运行的 artifact hash 差异。

LLM 可协助提出 fixture,但 golden expected 由人工确认后冻结,测试 runner 独立判定红绿。

## 9. 整版发布门

以下条件必须同时成立:

1. 所有 v2 fixture 与真实论文抽样的 wrong-page count、duplicate binding count 都为 0。
2. 输入指纹、artifact hash/schema、LID 唯一性、页边界、单调顺序、selection shard 完整性全部通过。
3. 当前公式密集论文不再因质量指标 stage-fail,至少进入 `degraded` Reader;可比 source-span coverage 严格高于 50.818%。
4. `char_exact | region_exact | partial | unmapped` 的操作矩阵由 Core、Rust API 和 Web 三层共同覆盖。
5. 既有 `pdf_source_map.v1`/`pdf_selection_map.v1` 书籍仍可读取,且未被自动迁移或覆写。
6. 同输入连续构建产生稳定的语义 artifact/hash;时间戳等审计字段不得进入内容 hash。

8. Core/Web/Rust 全量测试、类型检查、Web build、sidecar smoke 与 Setup build 全绿。
