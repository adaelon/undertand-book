## 2. 边界与全局纪律

每个切片必须满足:

1. 生产 `automatic_build_protocol.v2` 默认行为保持不变,直到 BP8 发布切换。
2. v2 task/artifact 只读兼容;新生命周期状态使用版本化协议,不得原地重写历史 lease/failure/receipt。
3. Work unit、input hash、policy fingerprint、candidate schema 和 public artifact shape 不因 dispatch 复用而变化。
4. 模型仍由 Codex harness 的专用 executor 执行;sidecar 不直连 provider。
5. Root 只接收 bounded receipt/dispatch summary,不得接收或中转 candidate payload。
6. 每个代码切片先有失败测试,完成后追加 `docs/代码链路.md`;组件或主数据流变化时同步 `docs/架构.md`。
7. 性能判定使用确定性事件重算、真实 harness/model 回放和 quality gate;不使用 LLM 自评。

全局禁止:

- 不删除、重建或降级 Quantification Essence 已关闭 Pass1。
- 不用 `--allow-partial`、空输出、reject-all 或降低 quality profile 换墙钟。
- 不把 dispatch manifest 当成 work unit 或 artifact freshness 输入。
- 不预先为 dispatch 内所有任务创建长 reservation;executor 只逐个激活当前任务。
- 不把 lease expiry 计为 semantic attempt,也不让无限 lease epoch 绕过 executor instability 门禁。
- 不把估算 Token 写入精确 usage,不把未知 model/reasoning 伪装成默认值。

## 3. 目标契约

### 3.1 生命周期身份

```ts
interface AutomaticBuildExecutionIdentityV2 {
  work_unit_id: string;
  semantic_attempt: number;
  lease_epoch: number;
  submit_revision: number;
}

type AutomaticBuildLeasePhase = "reserved" | "running";

interface PhaseAwareTaskLeaseV2 {
  version: "automatic_build_task_lease.v2";
  identity: Omit<AutomaticBuildExecutionIdentityV2, "submit_revision">;
  phase: AutomaticBuildLeasePhase;
  owner: string;
  token: string;
  reserved_at: string;
  reserve_expires_at: string;
  started_at?: string;
  run_expires_at?: string;
  target_ref: BuildTargetRefV2;
  input_hash: string;
  policy_fingerprint: ExtractionPolicyFingerprintV1;
}
```

状态机:

```text
PENDING
  -> RESERVED(epoch=N)
      -> RUNNING(start.json,run_deadline)
          -> COMMITTED
          -> SEMANTIC_FAILURE
               -> semantic_attempt + 1,lease_epoch = 1
          -> SUBMIT_REPAIR
               -> submit_revision + 1
      -> RESERVATION_EXPIRED
           -> same semantic_attempt,lease_epoch + 1
      -> RUN_EXPIRED
           -> same semantic_attempt,lease_epoch + 1

lease_epoch > max_lease_epochs
  -> needs_user(executor_instability)

semantic_attempt > 3
  -> needs_user(retry_exhausted)
```

Bootstrap:

```text
reserve_ttl = 10 minutes
run_ttl     = 30 minutes
adaptive_run_ttl = clamp(15m,ceil(1.5 * matched_service_p95),60m)
```

`input` 的第一个成功副作用是 create-only `start.json`;之后才读取并输出 extraction input。Heartbeat 只能延长 `running` 且 identity 完全匹配的 lease。16.2 分钟真实长任务在无 heartbeat 时也必须能完成。

### 3.2 调度执行包

```ts
interface ExecutorDispatchManifestV1 {
  version: "automatic_build_executor_dispatch.v1";
  dispatch_id: string;
  target_ref: BuildTargetRefV2;
  stage: AutomaticBuildStage;
  kind: WorkUnitKind;
  policy_fingerprint: ExtractionPolicyFingerprintV1;
  ordered_work_unit_ids: string[];
  limits: {
    max_units: number;
    max_input_tokens: number;
    max_predicted_service_ms: number;
  };
}

interface ExecutorDispatchReceiptV1 {
  dispatch_id: string;
  task_receipts: RootTaskReceipt[];
  unclaimed_work_unit_ids: string[];
  terminal_reason: "complete" | "task_failure" | "executor_interrupted";
}
```

约束:

- Planner 只生成 manifest,不 claim task。
- `dispatch.next` 每次最多 claim 一个 work unit;上一 task terminal 后才返回下一 task envelope。
- Task semantic failure 可记录 receipt 后继续下一 task;executor infrastructure failure 立即停止 dispatch。
- 已完成 task 保留;当前活动 lease 走 expiry/recovery;尚未 claim 的 task 始终 pending。
- Subagent 每完成一个 task 必须丢弃该 task 的 candidate body,下一 task 重新执行 input 命令;manifest 不提供输入正文。

### 3.3 性能事件与预算

```ts
type AutomaticBuildLifecycleEvent =
  | "dispatch_created"
  | "lease_reserved"
  | "executor_started"
  | "heartbeat"
  | "input_finished"
  | "candidate_submitted"
  | "writer_failed"
  | "task_committed"
  | "lease_expired"
  | "dispatch_finished";

interface AutomaticBuildWallBudgetV1 {
  max_wall_clock_minutes?: number;
  max_agent_starts?: number;
  max_duplicate_lease_ratio?: number;
  on_exceed: "needs_user" | "stop";
}
```

Preflight 必须分列:

```text
plan_lifetime_cost  = 全部 policy-bound eligible units
remaining_cost      = 当前 pending units
scheduled_cost      = 本轮 dispatch manifests
predicted_wall_p50  = list_schedule(dispatch predicted p50,max_workers)
predicted_wall_p95  = list_schedule(dispatch predicted p95,max_workers)
confidence          = sample_count + model_match + policy_match + harness_match
```

性能历史 key 至少包含 `stage/kind/router/model/reasoning_effort/harness_release`。历史 revision 不进入 artifact policy fingerprint,但影响预算结论时必须进入独立 `preflight_evaluation_digest`,避免用户接受的墙钟评估悄悄漂移。

## 4. 目标执行链

```text
plan(read-only)
  -> rebuild work-unit plan
  -> rebuild append-only performance summary
  -> plan dispatch manifests
  -> predict remaining wall clock
  -> user/harness accepts evaluation digest

next
  -> persist accepted dispatch manifest
  -> root launches one dedicated executor per dispatch

executor
  -> dispatch.next claims one task as RESERVED
  -> input atomically starts RUNNING
  -> model writes task-owned candidate
  -> submit validates and commits independent artifact
  -> dispatch.next repeats until bounded manifest complete
  -> executor returns bounded dispatch receipt

root
  -> validates receipt count/bytes
  -> returns to plan
  -> close stage only after existing integrity + quality gates pass
```
