## 0. 对齐确认单

**FrozenIntent**:修复显式“带我读”在首轮因导航工具延迟暴露且导航规则未注入而退化为 `search_text -> text -> 一次性总结` 的路由缺口；实现必须在首个请求计划前确定性预激活住户带读所需能力，让导航规则始终可见，并以单停靠点导航轨迹与 Goto effect 验收。不新增外部 reading skill，不调用 MCP 访客命令 `book_guide`，GR0 不修改运行时代码。

**TermMap**:

| 术语 | 状态 | 本方案对齐 |
|---|---|---|
| 工具暴露计划 | BOUNDARY_CHANGE | 本回合激活集新增“首轮前显式意图 seed”来源 |
| 延迟工具发现 / `tool.search` | EXISTING | 保留为漏匹配与其他能力的通用回退 |
| BookStructure / guide path / key_stop | EXISTING | 宏观结构与关键停靠点权威不变 |
| `guided_route_from` / TechnicalLearningAgentPolicy | EXISTING | 当前位置的局部教学前沿不变 |

| `book_guide` / 访客会话 | EXISTING | 只属外部 MCP，明确排除在 Resident 修复外 |

**RiskReceipt**:用户已明确同意“曝光前确定性识别带读意图、预激活导航能力、导航规则始终可见、增加真实路由回归”的方向。已知风险是匹配过宽会增加首轮 schema 或误导副作用，因此采用高精度闭集、只改变可见能力、保留权限/profile/schema 门，并把真实副作用限定在 `reader.gotoLid` 调用之后。

## 1. 现状与循环依赖

| 环节 | 当前实现 | 结果 |
|---|---|---|
| 回合初始化 | `orchestrator.rs::run_with_turn_resources_and_checkpoint_sink` 以 `ToolExposureState::default()` 开始 | 首轮 activated 为空 |
| 工具分类 | `tool_exposure.rs::classify` 把 structure/guide/routes 与 reader state/write 归为 Deferred | 首轮 schema 不含导航与 Goto |
| 计划生成 | `ToolExposurePlan::build` 只加入已 activated 的 Deferred 项 | 必须先 `tool.search`，下一次 sampling 才可用 |
| policy 选择 | `agent_prompt.rs::policy_modules_for_tools` 只在可见工具命中导航集合时加入 `NAVIGATION` | 首轮不知道显式带读应发现什么 |
| 既有回归 | `orchestrator.rs::tests::guided_read_one_stop_pipeline` 由 FakeAdapter 预写 discovery call | 证明管道可跑，不证明 prompt 路由 |

```text
当前:
explicit guided-read question
  -> activated = {}
  -> first tools = generic read/search + tool.search
  -> NAVIGATION absent
  -> book.search_text -> book.text -> final summary

目标:
explicit guided-read question
  -> deterministic turn hint
  -> seed resident navigation capabilities
  -> pre-turn budget + first AgentRequestPlan already see tools and NAVIGATION
  -> LOCATE? -> reader.state -> book.structure -> book.guide_path
  -> book.guided_route_from? -> book.text/context self-check
  -> reader.gotoLid -> book.synthesize -> STOP after one key_stop
```

预激活必须发生在 pre-turn `planned_request` 之前；否则活动上下文预算仍按旧的 8-tool 面估算，实际首轮新增 schema 会绕过预算审计。

## 2. 冻结契约

```rust
enum TurnIntentHint {
    ExplicitGuidedRead,
}

fn classify_turn_intent(question: &str) -> BTreeSet<TurnIntentHint>;

fn seed_turn_tool_activations(
    hints: &BTreeSet<TurnIntentHint>,
    registry: &ToolRegistry,
    context: &ToolExposureContext,
    state: &mut ToolExposureState,
);
```

`ExplicitGuidedRead` v1 只做大小写、首尾空白和闭集短语匹配；显式否定优先于肯定。第一版正例覆盖“带我读/带着我读/陪我读/一步步讲/接着带我读/接着讲这一节”以及 `guide me through`、`walk me through`；“总结本章/本章讲了什么/read this aloud”不命中，“不要/不用/别带我读”必须不命中。匹配器不解析章节语义、不决定目标 LID、不执行工具。

显式带读的首轮能力组由注册表派生，不复制第二份工具 schema：

| 来源 | 首轮允许能力 |
|---|---|
| `ToolCapability::Navigation` | `book.structure`、`book.guide_path`、route/guided route/unvisited/route-to；paper profile 另按既有 gate 包含 paper guide |
| 精确 Reader handler | `reader.state`、`reader.gotoLid` |
| 既有 Direct | `book.search_text`、`book.text`、`book.context`、`book.synthesize` 等保持原规则 |
| 明确排除 | 其他 Reader 写工具、memory/profile、外部 MCP `book_guide` |

每个受支持 `ModelRuntimeProfile` 都必须用 golden 证明完整允许组仍小于 `tool_schema_budget_bytes`；非带读回合的初始 tool schema golden 保持不变。激活只改 `ToolExposureState`，首个 Provider sampling 前 `Reader`、Memory、effects 与 trace 必须 byte-equivalent 于未激活状态。

`resident-agent.policy.navigation` 改为每次 Resident 业务 sampling 都注入，但 compaction、Book MCP visitor 与其他独立 agent prompt 不消费它。规则必须明确：

1. 显式带读不是章节摘要；仅定位并读到原文仍不能终答。
2. 先看 Reader state 与 BookStructure/guide path，再按需要取局部 guided frontier。
3. 非机械跳转遵守 ADR-0045，候选先经 `book.text/context` 自检。
4. 必须真实调用 `reader.gotoLid`；一次用户回合只能有一次改变 anchor 的 Reader 导航调用，并形成一个合并后的 Goto effect。
5. 只综合当前与新停靠点，讲完停下等待反馈，不一次性覆盖剩余路线。
6. 若匹配器漏掉表达且工具不可见，常驻规则仍指导模型用 `tool.search` 发现最小能力。

## 3. 验收轨迹

确定性集成夹具不再预写 discovery。首个 `AgentRequestPlan` 必须同时满足：

- instruction assets 含 `resident-agent.policy.navigation`；
- tools 含 `book.structure`、`book.guide_path`、`book.guided_route_from`、`reader.state`、`reader.gotoLid`、`book.synthesize`；
- tools 不含 `book_guide`，也不因带读激活 highlight/note/layout；
- Adapter 首次被调用前无 Reader 状态变化、effect 或 trace。

单停靠点 fixture 的结构断言：

```text
reader.state
  < book.structure
  < book.guide_path
  < [book.guided_route_from and/or book.text/context self-check]
  < reader.gotoLid
  < book.synthesize
  < final
```

`tool.search` 不得出现在该已命中 fixture；trace 恰有一次改变 anchor 的 `reader.gotoLid`，`effects` 恰有一个 `Goto(before_anchor, after_anchor)`；`after_anchor` 必须来自本轮 guide path/key stop 或 guided frontier；`book.synthesize.lids` 不得扩展到整节剩余路线。

真实回放使用事故原型提示“带我读 1.8.1 …”，由环境提供真实书目录与预期停靠点 `1.8.2`。回放报告 `guided_read_route_replay.v1` 只保存 book/source digest、provider/model/profile、prompt/exposure 版本、首轮工具名、工具参数摘要、trace、effects 与答案摘要，不保存原文、Tool body、API key 或 Reader 私有记忆。确定性 verifier 必须证明：BookStructure/guide path 可用且含预期停靠点；没有仅 `search_text -> text` 后终答；发生导航读取与唯一 Goto；目标属于返回路线；未调用 `book_guide`。

## 10. 发布硬门禁

1. 显式带读的首轮 request 必须同时看见导航 policy 与完整允许工具组。
2. 非带读首轮工具 schema golden 不得膨胀；只有小型 navigation policy 常驻。
3. seed、discovery 与 hidden/permission/profile/schema gate 不得互相绕过。
4. 意图命中本身不得执行工具、改变 Reader/Memory 或产生 effect。
5. `book_guide` 不得进入 Resident ToolRegistry、request、trace 或回放报告。
6. 已命中带读不能在仅 `search_text/text` 后终答，也不能一次讲完整节。
7. 非机械 Goto 前必须读候选真实原文/上下文；目标必须来自已观察路线。
8. 一个带读用户回合只能有一次改变 anchor 的 Reader 导航调用和一个合并 Goto effect，讲完必须停下等反馈。
9. FakeAdapter 只承担结构回归；发布必须另有真实模型的结构化回放证据。
10. 任何验收都以工具面、trace、参数、route membership 与 effect 为确定性判据，不以 LLM 自评为判据。
