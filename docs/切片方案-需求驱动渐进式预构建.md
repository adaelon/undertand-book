## 0. 对齐确认单

**FrozenIntent**:导入后先完成不依赖语义模型的立即可读基础层,再让用户选择先阅读、标准深读或描述目标;自然语言只生成可编辑的 `BuildIntent` 与 `BuildPlan` draft,用户确认产物、范围、复用、估计和预算后才执行昂贵工作。当前完整 Pass1/profile sidecar/Pass2/BookStructure 保留为 `standard_deep` 默认配方模板。本方案不把用户目标写入公共书真相,不从阅读行为自动推断授权,不在 IP0 修改运行代码。最终以 reader 不等待语义构建、未确认计划零昂贵调用、标准深读产物保持兼容、目标产物私有且可独立重建为成功标准。

**TermMap**:

| 术语 | 状态 | 本方案定义 |
|---|---|---|
| 一键预构建 | BOUNDARY_CHANGE | 执行已确认计划,不再等价于导入后全量自动构建 |
| content profile / BookStructure | EXISTING | 继续描述公共内容规则与公共结构理解 |
| BuildDecisionRequest | BOUNDARY_CHANGE | 增加不伪装成某个 stage 的 build-plan scope |
| 立即可读基础层 | NEW | 首次语义模型调用前形成的可信 source/LID/reader 基座 |
| 标准语义配方 | NEW | 当前 goal-agnostic 全量公共语义产物模板 `standard_deep` |
| BuildIntent | NEW | 用户显式确认、reader-private、版本化的单书构建目标 |
| BuildPlan | NEW | 目标/标准配方对应的依赖闭包、复用、估计、预算与 digest |
| 目标产物层 | NEW | 绑定 intent/plan/source 与 LID evidence 的 reader-private overlay |

**RiskReceipt**:用户于 2026-07-25 明确同意该产品方向。已知风险是把目标注入公共抽取会破坏缓存与隐私,而把目标层完全独立又会新增私有存储、计划确认和跨执行面的契约;因此标准语义层保持 goal-agnostic,目标层复用公共 LID/artifact 并受 `ReaderPrivateStorageGate` 保护。

**ChangeType**:`[边界重构]`。

领域对齐完成;TermMap 零未解析符号。

## 1. 产品不变量与验收信号

| 不变量 | 确定性验收 |
|---|---|
| 先读后建 | 立即可读基础层通过后 `route=reader`,即使无 intent/plan 或语义 stage 全缺失 |
| 未确认不花费 | 无 confirmed plan 时无 semantic task lease、executor run 或 provider request |
| 标准能力不退化 | `standard_deep` 的 stage closure、policy fingerprint、artifact schema 与当前完整构建一致 |
| 目标不污染公共层 | public semantic prompt/fingerprint 不含 `intent_id`、raw goal 或 reader memory |
| 目标产物可验证 | 每个 accepted record 有真实 LID evidence,source/intent/plan digest 全匹配 |
| 目标改变不重建全书 | replan 只新增/取代目标 overlay 与缺失公共依赖,fresh public artifact 继续复用 |
| 私有边界关闭 | Visitor、Book MCP、普通书目录扫描和未授权 Workbench snapshot 看不到 intent/overlay |
| 成本可知 | 确认面同时显示 token 上界、墙钟区间/未知项、历史匹配置信度与预算漂移动作 |

产品遥测只记录枚举、digest、计数、耗时、token 与产物消费事件,不得记录原始目标文本或目标产物正文。首轮基线指标:

```text
time_to_first_readable
intent_draft_to_confirm
time_to_first_goal_artifact
estimated_vs_actual_tokens
estimated_vs_actual_wall_clock
artifact_opened_or_cited_within_7d
standard_deep_vs_goal_directed_selection
plan_revision_and_budget_reconfirmation_rate
```

IP9 先建立基线,不在无数据时虚构转化率阈值。发布硬门只使用本节不变量与真实书回放。

## 2. 首版范围

产品模式:

| 模式 | 用户动作 | 构建行为 |
|---|---|---|
| `read_now` | 先阅读 | 不创建昂贵计划;以后可再次打开构建方案 |
| `standard_deep` | 选择标准深读并确认 | 执行当前 content-profile 的完整公共语义配方 |
| `goal_directed` | 陈述目标、审阅并确认计划 | 只构建能力依赖闭包与 reader-private 目标产物 |

首版 capability registry 只登记已有契约可承接的能力:

```text
public.standard_deep
private.timeline
private.concept_map
private.comparison_table
private.argument_map
```

`custom` 只允许用户编辑 schema 后二次确认,不得由 Planner 自动选择。方法清单、学习路线、复现步骤、习题生成、跨书项目和团队共享留后续 capability ADR;首版不得用自由 prompt 假装这些 schema 已稳定。

全局禁止:

- 不让 `BuildIntent` 改写 source、LID、content profile、公共 graph、BookStructure 或 ReaderProfile。
- 不把 `balanced/sparse/full` 直接映射成用户产品模式。
- 不让 LLM 自行声明 plan 合法、预算可接受、artifact fresh 或 evidence 有效。
- 不把 raw goal 写入 `.understand-book/<book_id>`、job event、stdout/stderr、遥测或 MCP 返回。
- 不为 goal-directed 新建第二条 source/LID/pipeline;只登记 capability 和依赖。
- 不删除、降级或重跑已有 fresh 标准语义 artifact。

## 3. 目标契约

```ts
type BuildIntentStatus = "draft" | "confirmed" | "superseded" | "stale_source" | "deleted";
type BuildRecipeId = "standard_deep" | "goal_directed";
type IntentArtifactType = "timeline" | "concept_map" | "comparison_table" | "argument_map" | "custom";

interface BuildIntentV1 {
  version: "build_intent.v1";
  intent_id: string;
  revision: number;
  book_id: string;
  source_fingerprint: string;
  content_profile: { id: string; version: string };
  user_goal: string;
  goal_kind: "learn" | "analyze" | "compare" | "write" | "reference" | "other";
  source_scope: { whole_book: boolean; lids: string[]; sections: string[] };
  desired_artifacts: IntentArtifactType[];
  usage_horizon: "one_off" | "project" | "long_term";
  privacy: "reader_private";
  status: BuildIntentStatus;
  created_at: string;
  confirmed_at?: string;
  supersedes_intent_id?: string;
}

interface BuildPlanEstimateV1 {
  input_tokens: { lower: number; upper: number; coverage: number };
  output_tokens: { lower: number; upper: number; coverage: number };
  wall_clock_minutes: { p50?: number; p95?: number; confidence: "none" | "low" | "medium" | "high" };
  unknown_stages: string[];
  historical_match: { stage: boolean; policy: boolean; model: boolean; harness: boolean; sample_count: number };
}

interface BuildPlanV1 {
  version: "build_plan.v1";
  plan_id: string;
  revision: number;
  book_id: string;
  source_fingerprint: string;
  content_profile: { id: string; version: string };
  recipe_id: BuildRecipeId;
  intent_id?: string;
  intent_digest?: string;
  public_stage_closure: string[];
  private_artifacts: Array<{
    artifact_id: string;
    artifact_type: IntentArtifactType;
    source_scope: BuildIntentV1["source_scope"];
    required_public_capabilities: string[];
    evidence_policy: "lid_required";
  }>;
  reuse: Array<{ artifact: string; freshness_digest: string }>;
  create: string[];
  excluded: Array<{ artifact: string; reason: string }>;
  estimate: BuildPlanEstimateV1;
  budget: {
    max_total_tokens?: number;
    max_wall_clock_minutes?: number;
    on_exceed: "needs_user";
  };
  status: "draft" | "confirmed" | "superseded" | "stale_source" | "completed";
  plan_digest: string;
  confirmation_source?: "reader_ui" | "explicit_legacy_command";
  created_at: string;
  confirmed_at?: string;
}
```

Digest 规则:

```text
intent_digest = sha256(canonical_json(intent excluding timestamps/status))
plan_digest   = sha256(canonical_json(
  source_fingerprint,
  profile id/version,
  recipe_id,
  intent_digest?,
  public_stage_closure,
  private artifact contracts,
  reuse/create/excluded,
  accepted budget
))
```

估计值和历史样本不进入 `plan_digest`;用户确认的是目标与预算上限,不是会随新样本变化的预测。ADR-0092 的 `preflight_evaluation_digest` 记录当次预测。若累计实际值加剩余预测超过确认预算,返回 `needs_user(plan_budget_exceeded)`。

标准配方闭包:

```text
technical_learning.standard_deep =
  pass1 -> profile_sidecar -> pass2 -> book_structure

paper.standard_deep =
  pass1
    -> paper_metadata
    -> paper_lexicon
    -> profile_sidecar -> pass2 -> book_structure -> paper_reading_guide
```

具体目标 artifact 由 capability registry 声明最小公共前置条件。首版四种私有 sidecar 默认只要求立即可读基础层;若后续某 schema 需要 graph/BookStructure,必须在 registry 中显式声明并由确定性闭包补全,不得在 executor prompt 中偷加依赖。

## 4. 状态机与数据流

产品状态机:

```text
INPUT_IMPORTED
  -> FOUNDATION_BUILDING
  -> FOUNDATION_NEEDS_REVIEW -> user decision -> FOUNDATION_BUILDING
  -> READER_READY
       -> READ_NOW
       -> INTENT_DRAFTING
            -> INTENT_DRAFT
            -> PLAN_DRAFT
                 -> user edits/rejects -> INTENT_DRAFTING
                 -> user confirms plan_digest -> PLAN_CONFIRMED
                      -> BUILDING_PUBLIC_PREREQUISITES
                      -> BUILDING_PRIVATE_ARTIFACTS
                      -> PLAN_COMPLETED
                      -> budget/source/permission drift -> NEEDS_USER
       -> STANDARD_PLAN_DRAFT
            -> user confirms plan_digest -> PLAN_CONFIRMED
```

重新计划:

```text
confirmed intent A + plan A
  -> user changes goal/scope/output
  -> draft intent B(supersedes=A)
  -> plan B recomputes reuse/create/excluded
  -> confirm B
  -> A becomes superseded but remains auditable
  -> public fresh artifacts reused
  -> only B overlay becomes active
```

来源变化:

```text
source_fingerprint changes
  -> intent/plan/overlay = stale_source
  -> Reader follows existing source trust rules
  -> user reviews regenerated plan against new source
  -> no stale target artifact may be projected
```

端到端数据流:

```text
Reader explicit request
  -> resident-only intent draft endpoint
  -> optional structured LLM candidate
  -> deterministic capability/schema/scope validator
  -> BuildPlan compiler + artifact freshness inspection
  -> total estimate + unknown coverage + budget
  -> user confirms exact plan_digest
  -> build controller passes opaque private plan path to Build Engine
  -> public prerequisites run under existing policy-bound pipeline
  -> private task mailbox/executor writes candidate under private root
  -> deterministic schema/LID/source/intent/plan gate
  -> resident reader projects active overlay
```

`BuildDecisionRequestV2` 不得伪造 stage:

```ts
type BuildDecisionScopeV2 =
  | { kind: "stage"; stage: BuildStageId }
  | { kind: "build_plan"; plan_id: string; plan_digest: string };

interface BuildDecisionRequestV2 {
  version: "build_decision_request.v2";
  decision_id: string;
  job_id?: string;
  scope: BuildDecisionScopeV2;
  kind: "build_intent_plan" | ExistingBuildDecisionKind;
  options: Array<{ id: string; label: string; description?: string }>;
  status: "pending" | "answered";
}
```

V2 job event 只记录 `intent_id/plan_id/plan_digest/answer enum`,不记录 `user_goal`。

## 5. 私有存储与消费边界

默认物理布局:

```text
<home>/.understand-book/private/build-intents/<book_id>/
  index.json
  intents/<intent_id>/intent.json
  plans/<plan_id>.json
  artifacts/<intent_id>/<artifact_id>/
    candidate-mailbox/
    accepted.json
    receipt.json
```

可由 `UNDERSTAND_BOOK_PRIVATE_DIR` 覆盖根目录;根目录和每个文件都必须通过 `ReaderPrivateStorageGate` 的真实目录、无 symlink、当前 OS 用户权限检查。标识符必须先过 ASCII-safe/path traversal validator,不能直接拼接用户文本。

访问矩阵:

| Surface | Intent/Plan | Target artifact | Public semantic artifact |
|---|---:|---:|---:|
| Resident Reader | 读写 | 读取当前 active overlay | 读取 |
| Authorized build controller | 读 confirmed plan/写状态 | 写 candidate/accepted | 构建/读取 |
| Build executor | 只读当前 task envelope | 写 task-owned candidate | 只读声明的输入 |
| Build Workbench snapshot | 仅 redacted status/digest | 不读正文 | 读构建状态 |
| Visitor session | 禁止 | 禁止 | 读取 |
| Book MCP Sidecar | 禁止 | 禁止 | 只读 canonical Book tools |

私有 store 不可用时返回 `READER_PRIVATE_STORAGE_UNAVAILABLE`;不能把 intent/overlay 回退到书目录。`standard_deep` 只产生公共产物,仍可在用户显式确认后运行。
