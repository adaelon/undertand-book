## 0 对齐与交付边界

**FrozenIntent**：修复已证实的重复状态工作与 Executor 交接故障，减少完成同一批有效语义工作所需的墙钟；D0 交付 ADR、证据和实施计划，B1 交付代表性磁盘夹具、可重复基线与计时。

**授权依据**：用户在根因与分步修复建议后明确要求“那就落 adr 和切片方案来解决这些问题”。

| 术语 | 对齐状态 | 本方案口径 |
|---|---|---|
| work unit、semantic attempt | EXISTING | 一个语义工作单元独立提交；控制恢复不消耗语义尝试 |
| recovery generation、bootstrap epoch | EXISTING | 使用 ADR-0117 的持久恢复身份和幂等推进规则 |
| dispatch slot | EXISTING | 同一调度运行的占位键，不是可反复派工的 child |
| dispatch bundle | EXISTING | 一组独立 work units 的调度信封；V4 可跨多个单引用 child 完成 |
| accepted artifact、freshness | EXISTING | 结果复用由既有语义身份和持久验收事实决定 |
| 快照、准备、调用内复用 | 实现级 | 控制代码的读写职责与生命周期，不新增领域对象或 CONTEXT 术语 |

术语对齐完成。此次澄清不改变 work unit、attempt、lease、slot 或产物身份的定义；V4 的 child 生命周期按既有实现收紧表述。

**风险控制**：后续优化可能漏看并发提交或误放行过期执行权；P2–P4 必须保留当前 target/source/policy、owner、lease 与 terminal 检查。当前文档切片不触碰这些运行边界。任何需要放宽它们的实现均退回设计，不在本方案内默认通过。

**完成判据**：每个问题有证据、归属切片、红测、量化指标和停止条件；D0 的引用、编号、证据算术与文档差异检查通过。实现每刀单独 commit-ready，不混入无关清理。

## 2 固定不变量

- 既有 source/input/prompt/semantic contract、work-unit identity、artifact freshness 和 accepted bytes 不变；Pass2 与并发设置由原确认计划决定。
- 不通过抬高 transport 预算、增加语义重试、删除旧状态或提升 policy generation 取得性能收益。
- claim/start/submit 仍读取当前执行权与终态；stale/expired sink 不能提交；DONE 仍等待 durable commit。
- 单引用 child、exact-four MCP、Root 不取得正文/候选、`completed_refs` 去重和每 slot 最多一个 live child 保持成立。
- 准备与读取复用现有文件、policy/migration/dispatch/task 协议；不引入新哈希、全局缓存、常驻 worker 或兼容框架。

## L1 新引用新执行器与即时补位

**做**：Root 对每个 Driver 新 ref 创建新的专用 child；调度槽只限制同时占用数。收到一个终态时立即吸收已经到达的其他终态，不等待尚未完成的 child，再计算当前可用槽位。

```text
on terminal(child):
  remove only that child's live slot; retain its ref in completed_refs
  consume other terminal observations already delivered
  retain each pending failure observation until a structured step response
  step with current available capacity and one pending observation
on SPAWN_EXECUTORS:
  for launch with free slot and unseen ref:
    spawn a new dedicated child; never followup an old terminal child
```

Driver 调用期间新到达的终态在返回后先入账，下一 step 按最新容量提交；不把调用前的空闲数当作之后的固定事实。

**触达**：`skills/build/SKILL.md` 与 thin-plugin 副本；`agents/automatic-build-dispatch-executor.md`、规范 agent asset 与发布投影中相应生命周期文字；`packages/core/test/codex-executor-agent.test.ts`；真实宿主 canary。

**红测**：三槽完成首波后，对第二波必须观察到三个新 child 身份、零 followup 派新 ref；另两个 child 尚 live 时，已空闲槽收到新工作。已有 slot 或 completed ref 的重复 launch 不产生第二个 child。

**验收**：连续两波至少 6 个独立 units 全部 durable commit；每 ref 最多启动一次、每 slot 最多一个 live child。bootstrap 失败观察不能因另一个 child 成功或先出现 NEEDS_USER 而丢失。补位空窗不含仍有真实依赖阻塞的时间。

**停止/回滚**：出现同 slot 双 live、旧 child 新引用、丢失未上报失败或复用集合缩小时停止；先在 fixture 撤回本刀，真实控制记录不删除。

**本地验收（2026-09-08）**：Root 与全部 Executor 资产同步单引用生命周期、已送达终态消费和逐项失败队列；NEEDS_USER 保留发送项，避免观察尚未处理就被清除。三槽 fixture 使用六个独立真实 MCP session 完成六个单元，另两个生成尚未提交时补位，每单元 attempt 1。另有启动错峰红例：兄弟 child 尚未 open 时，Driver 补充返回同 run 已准备的当前引用，让 Root 选到实际空槽的替补；因此触达增加 `automatic-build.ts:expandAction` 与 `automatic-build-driver.ts:automaticBuildStep`。宿主 child/队列执行与空窗仍待 V1，见[证据与限制](performance/understand-book-l1-l2-lifecycle.md)。

## L2 连接诊断与有界恢复闭环

**做**：把实际连接状态拒绝和版本不兼容分开；对“新引用没有打开成功，但对应 child 已终止”的已知故障给 Driver 一条精确观察通道。

**诊断合同**：连接终态拒绝 -> `session/connection_terminal/open`；连接绑定另一 ref -> `session/handoff_ref_mismatch/open`。其他已有 lease、sink、transport、writer 诊断保持原分类。真正版本/请求协议不兼容仍用 `protocol_incompatible`；不得根据该宽泛旧码推定是哪种连接错误。

**Driver 请求增量**：在当前 step 请求增加以下可选闭合字段，与 `bootstrap_failure` 互斥；旧请求仍合法，旧 durable records 与 ref 派生不改。

```ts
executor_open_failure?: {
  opaque_handoff_ref: string;
  diagnostic_code: "connection_terminal" | "handoff_ref_mismatch";
  phase: "open";
}
```

这是 Root 生命周期观察，不是任务失败权威。Driver 验证 ref 属于本 invocation、仍是 current generation、且无 durable open 后，复用已有幂等启动恢复记录和 bootstrap epoch 推进；不增加 semantic attempt 或 lease epoch。重复观察只推进一次，新 ref 的 slot 保持不变。三次连续启动失败沿用 NEEDS_USER 与显式 `retry_bootstrap`；不扩展自动重试预算。

若检查发现该 ref 已 open、任务已提交或代际已变化，持久事实优先，不再记录“未打开失败”。Root 保留真实诊断，不将其改写成 `bootstrap_unavailable`。历史不精确的 `protocol_incompatible` 保持安装/恢复人工边界，不凭推测授予自动换代。

**触达**：`packages/core/src/build-executor-connection-capability.ts`、`build-executor-tool-adapter.ts`、`automatic-build-executor-session.ts`；`skills/build/build-executor-mcp.ts`、`automatic-build-driver.ts`；相应 Agent/skill 投影和 connection/adapter/MCP/session/driver tests。

**红测**：同连接 A 成功 DONE 后打开 B，返回精确连接码而非版本码；Root 上报未 open 的 B 后获得同 slot 新 ref；新 child 完成 B。重复上报、错误 invocation、已 open B、已提交 B、旧代际 B 均不能错误推进。三次暂停和一次显式授权仍成立。

**验收**：连接错误不再导致重复旧 ref 的永久空转；accepted A 不产生新 attempt；B 的首次有效生成仍是 semantic attempt 1。分类、请求、Driver 和发布投影同时验收。

**停止/回滚**：若必须凭 child 自报覆盖 durable truth 才能继续，停止该设计；新字段发布前可撤回未发布代码，发布后按 ADR-0117 向前修复，不清空 registry。

**本地验收（2026-09-08）**：精确诊断、闭合观察字段、Driver 恢复和所有投影已实现；协议自检同步识别精确拒绝。A 提交后同连接打开 B 的拒绝经 Driver 换代，B 在同 slot 新连接提交，accepted A 不产生额外 attempt。幂等/归属/已打开/已提交/旧 ref 与三次暂停、显式重试均有覆盖。compiled smoke 同时验证两种精确拒绝及原版本负例，见[验收记录](performance/understand-book-l1-l2-lifecycle.md)。

## P1 阶段策略与迁移登记去重

**做**：先去掉同一次 routing 内对相同 policy set 的逐单元重复冻结。准备好一个阶段的唯一策略集合后，内部 migration/adoption 路径复用已校验的集合；单独公开入口仍能正确准备所需策略。已有文件走读取/内容比较；只有缺失时才尝试 create-only，真正并发首次创建仍保留 EEXIST 后复核。

**触达**：`build-orchestrator.ts:routePass1ProductionStage/routeProfileSidecarProductionStage/applyAutomaticBuildProductionMigration`；`automatic-build-policy-generation.ts:freezeAutomaticBuildStagePolicySet/recordAutomaticBuildPolicyMigration/recordAutomaticBuildPriorGenerationAdoption/persistMigrationReceipt`；policy-generation 与 orchestrator tests。

**红测**：B1 暖快照当前出现大量 mkdir/write/EEXIST；目标为已准备策略及相同迁移回执的新增 mkdir/write/EEXIST 均为 0，策略冻结/读取次数随本次涉及的唯一 policy 成员数增长，而不随 work-unit 数重复乘算。

另测空 store 首次创建、已有相同内容、已有冲突内容，以及两个受支持调用首次准备同一策略；冲突仍得到原有恢复结果。直接比较 artifact/receipt/progress bytes 与 pending 集合，确认没有以跳过验收换取快路径。

**验收**：单测计数达标；同一 fixture 三次暖样本中位数下降且语义结果不变。报告 snapshot 总耗时，不以减少异常数量单独宣布提速。

**停止/回滚**：若既有不兼容策略被静默接受或迁移结果改变，回改本刀；不顺带调整 migration policy 或产物版本。

**本地验收（2026-09-08）**：routing 内唯一 policy set，迁移/接管内部复用；已有策略和回执先读直比，首次创建碰撞仍复核。重放红测的 mkdir/write 合计 6 → 0，B1 同规模 P1 四轮采样通过，暖 snapshot 12.203 s → 1.825 s。最终证据见 [P1–P4 验收](performance/understand-book-p1-p4-control-plane.md)。

## P2 只读快照与显式阶段准备

**做**：从正常 snapshot 路径移出写入、旧代次接管和迁移回执登记。利用现有阶段初始化/迁移入口执行已获授权的准备；首次构建、旧工作区恢复和策略变化继续沿用原有授权与恢复动作。

```text
new or changed stage -> inspect preparation requirement
  -> existing authorized preparation/migration command
  -> persist existing policy/task/receipt facts
prepared stage -> read snapshot without mutation
unprepared read -> derived preparation_required -> authorized Driver preparation
conflicting read -> existing recovery envelope -> Driver
```

快照不是偷偷修复状态的命令。准备未完成时不得把缺失产物误判为永久失败，也不得在 `legacy-plan`/读取时默默接管旧数据。按计划已授权的确定性准备不增加无意义确认；需要额外迁移授权的情况继续停在原边界。

**触达**：`build-orchestrator.ts` 的 production routing；`skills/build/automatic-build.ts` 的 plan/next/初始化与迁移入口；相关 policy/task store。沿用四类 Driver action，不新增公开第五种动作。

**红测**：已准备 workspace 连续两次 snapshot/plan 的持久文件内容和目录集合不变，写调用为 0；空工作区、新 stage、旧已接受产物的精确接管、策略冲突分别走正确准备/恢复路径。Pass1 closed 后仍保持原 freshness 结果。

**验收**：读取可独立测量；migration/adoption 的遍历和写入不再每次进入已准备阶段；旧 workspace 的 reuse/create/pending 集合与原授权规则一致。

**停止/回滚**：如果未准备状态只能靠 snapshot 隐式修改才能续跑，先补准备入口的闭环，不发布半套只读接口；数据格式不变，未发布实现可回退。

**本地验收（2026-09-08）**：snapshot/plan 零写入；未准备阶段使用派生 `preparation_required`，Driver/Next 经现有计划授权后显式准备，再刷新 pending/预算；冲突仍返回既有恢复 envelope。旧产物接管在准备入口完成，原 accepted bytes 与 freshness 断言保持。没有新增持久格式或 Root action。

## P3 Driver 单次决策段复用

**做**：同一 `build.step` 内，对没有发生相关状态变化的 plan/next 判断共享已读取 snapshot 与派生描述；将静态安装合同检查与按任务增长的状态审计分开，避免在每个阶段反复扫描全部历史 attempts。

**触达**：`skills/build/automatic-build-driver.ts:loadDriverState/automaticBuildStep`；`skills/build/automatic-build.ts:automaticBuildPlan/expandAction/automaticBuildProtocolDoctor`；`automatic-build-driver.test.ts`。

| 边界 | 复用规则 |
|---|---|
| 同一次 step 内纯 plan、budget、next 判断 | 共享该决策段已读取状态 |
| 本次 step 执行了准备、迁移、claim、失败登记、close/publication 等相关写入 | 丢弃受影响视图，在继续判断前刷新 |
| 其他 child 同时完成或租约过期 | claim/恢复/terminal 门读实时任务事实；下一 step 必须看到提交 |
| 新的 build.step 或进程 | 重新读取，不复用上次内存结果 |
| 插件/源/计划变化 | 保留当前协议与授权检查，不以缓存证明一致 |

**红测**：无写入的 active-dispatch 重放路径中，完整 snapshot 从多次降为一次；写入后不能返回旧 pending/ref。注入“plan 后另一个 child 提交”“claim 前租约到期”“close 后进入下一 stage”的事件序列，证明没有重复 claim、旧恢复引用或错误 DONE。

**验收**：B1 的 step 总耗时下降，同时 snapshot 次数符合实际读写边界；不靠取消 protocol doctor、预算或计划确认门取得收益。

**停止/回滚**：需要跨请求全局缓存或无法说明视图失效点时停止，保持已有慢路径；不新增 version flag、缓存指纹或后台同步器。

**本地验收（2026-09-08）**：active-dispatch 无写入决策段完整 snapshot 为 1，准备/失败登记/close 后重新读取。安装合同每次完整检查，历史 attempt 审计保留在显式 doctor。plan 后另一 child 提交的注入测试通过；B1 暖 step 50.690 s → 4.092 s。

## P4 Executor 单任务读取

**做**：让 `taskDescriptor`/delivery context 使用当前 dispatch、既有持久 task/descriptor、policy 和 frozen input；操作当前单元时只读取它与真实依赖。无关 Pass1/sidecar units 不再因 input.next/start/submit 被重新规划。

**触达**：`automatic-build-executor-session.ts:taskDescriptor/resolveDeliverySessionContext/nextAutomaticBuildExecutorInput/startAutomaticBuildExecutorGeneration/submitAutomaticBuildExecutorCandidateV3`；既有 task store、generation task readers；session/adapter/MCP tests。

**当前性义务**：target/source/profile；当前 policy generation 与 semantic contract；dispatch/run/work-unit；owner/recovery/lease/terminal；input binding 与完整 output contract；reduce 类型真实依赖的 accepted receipts。每个义务映射到现有权威记录，不能用 Root 的 launch projection 替代。

正常已准备路径的全书 snapshot 调用数目标为 0，初始化/迁移写入目标为 0。当前任务或依赖不再匹配时返回既有类型化 stale/recovery 结果，由 Driver 重新规划；不在 MCP 内创建隐式全书修复。

**红测**：open -> batch -> start -> submit 之间分别改变上述有意义的状态，原有拒绝与恢复结果保持；不相关单元新增成功 receipt 不强迫当前 frozen input 重新渲染。历史 V3 continuation 与当前 V4 单元终态分别测试，不误把旧模式改成新模式。

**验收**：相同四次调用保持完整交付、1 attempt/1 commit；在 205/315 规模 fixture 上 operation 和总处理耗时下降，当前任务之外的无关规模增加不会再等比例放大每次 input.next。真实依赖增加的成本单列。

**停止/回滚**：任何当前性义务无法由已有记录表达时先定位必要的最小读取，不直接删除该检查；若需要改 semantic identity 或新增通用缓存层，退回设计。

**本地验收（2026-09-08）**：当前 frozen task、policy、binding 与真实依赖定向读取；四次 MCP 完整 snapshot 均为 0，合计暖中位数 125.244 s → 4.070 s。四个操作的 policy 漂移和 reducer 子产物缺失使用既有 stale/session 错误；BookStructure 投影变化保持拒绝。派工推进追加前一失败任务的必要依赖，保留混合成功/失败批次和重试耗尽行为。每轮仍 1 attempt/1 commit，269 个已有 artifact 字节不变。

## V1 发布与多波性能验收

**做**：把单元正确性、compiled 路径、宿主能力和连续多波运行放到同一发布门。发布/安装及真实书续跑仍需进入对应执行授权，不由 D0 自动触发。

**入口**：既有 `apps/desktop/scripts/smoke-t7-executor-release.ts`、`smoke-t7-codex-cli-release.ts`、`smoke-automatic-build-parity.mjs`、`assert-plugin-release.mjs` 和 local 插件发布流程。性能轨迹复用 B1，不另建常驻基准系统。

1. source/compiled/thin-plugin/Agent/skill 的协议投影一致；安装态与发布候选直接比对。工具名测试不能代替真实 child 连接测试。
2. 当前受支持宿主完成至少两波、三槽、6 个独立 units；后续引用使用新 child。四种工具真正被调用并形成 durable commits。
3. 单独的恢复 canary 让一个槽位零调用失败，另两个继续；再验证 connection-terminal 的有界恢复。失败阈值、人工选择和语义尝试分账均成立。
4. 对照相同起始状态，记录 snapshot/step/MCP/first-open-to-commit、文件操作、refill 空窗、live-slot 区间、attempt/commit 数及 artifacts；Root/child final/公开 evidence 不含正文或候选。
5. 三次有界 fixture 暖跑中位数下降；真实多波 canary 的总墙钟和成功吞吐改善，且没有以更多重试或较少工作换取结果。真实宿主样本不足时标为未验证，不宣布整书提速。
6. 真实书只恢复原计划、invocation 和明确 workspace 下的 pending 工作，先验证 accepted 集合未缩小；保持 Pass2 disabled 和原并发授权。

**停止条件**：漏失 accepted 结果、重复 attempt/commit、错误 source/policy 被接受、旧引用空转、slot 双 live、计时不匹配或发布投影不一致，立即停止该次 canary/发布，返回对应 L/P 切片。

**回滚**：无真实控制记录变化时可恢复前一已备份程序与插件；出现新恢复观察后按 ADR-0117 向前修复。不得删除旧 registry、book workspace 或成功结果作为回滚手段。

**候选验收（2026-09-08）**：当前源码重建、Node/compiled parity、source/Agent/skill/thin-plugin 与隔离安装字节直比通过。Codex 0.153.4 两轮真实三槽六单元均 6 attempts/6 commits，新引用均用新 child；总墙钟 211.812 / 188.062 s。第二轮 24 次 MCP 逐连接配对，server/outer 合计 9.840 / 10.388 s；compiled 三槽恢复验证零调用失败、兄弟继续、terminal 拒绝、三次暂停与显式 retry。B1 同规模暖中位数 snapshot 1.501 s、step 4.060 s、四次 MCP 4.086 s，269 个已有 artifacts 字节不变。宿主新增 numeric duration 的轨迹红例已修复；25 项轨迹、23 项发布合同、2 项性能及类型检查通过。完整证据和未验证边界见 [V1](performance/understand-book-v1-release.md)。
