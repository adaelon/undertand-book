## 2. 冻结边界

### 2.1 必须保持

1. 模型推理继续只发生在 Codex harness；Sidecar 不读取 provider key，不直接请求模型。
2. Handoff 与 mailbox 继续物理持久化、create-only、attempt/run scoped，并支持普通 resume。
3. 生产者和消费者两端的路径、hash、schema、identity 重验都保留，失败关闭。
4. Root 不读取 prompt、task input、candidate、raw goal、LID 列表或 mailbox 正文。
5. 专用 executor 可读取完成语义生成所需的 prompt/input，但 candidate 不经 root 中转。
6. BuildPlan、work unit、artifact、lease、semantic attempt、quality、publication 与 retry 语义不变。
7. 用户确认继续绑定 Reader/Core 当前 `plan_id + plan_digest`；代码只隐藏 digest 搬运，不取消确认。
8. Pass2、预算扩大、计划漂移、迁移与 retry reset 仍须显式用户选择。
9. `available_agent_slots` 仍由 Codex 根据实时 harness 容量提供；Sidecar 不猜 agent 槽位。
10. 旧 `protocol-doctor/plan/next/dispatch.*/input/candidate/submit/fail/close` 在迁移期保持内部兼容和显式 rollback。

### 2.2 明确不做

- 不删除 mailbox、handoff、receipt、lease 或质量闸。
- 不让 Build Engine 启动、等待或取消 Codex subagent。
- 不把 candidate、prompt 或 task input 放进 `build.step` 响应。
- 不把对话记忆、subagent 最终文本或 root 收集的 receipt 列表作为恢复权威。
- 不改变 semantic extractor prompt 字节、输出 schema 或既有 `prompt_sha256`。
- 不重写历史 plan、dispatch、attempt、receipt 或 accepted artifact。
- 不在本项目中减少 `proof_digest/policy_set_digest`，也不改变它们参与 freshness 的深度；该问题另立 ADR 与迁移切片。
- 不以缩短 `SKILL.md` 先行掩盖 driver 尚未闭合；skill 切换必须最后发生。

## 3. Root 目标接口

### 3.1 版本化响应

```ts
type AutomaticBuildStepActionV1 =
  | {
      kind: "SPAWN_EXECUTORS";
      executors: Array<{ opaque_handoff_ref: string }>;
    }
  | {
      kind: "WAIT";
      reason: "active_executors" | "active_lease" | "backoff";
      retry_after_ms: number;
    }
  | {
      kind: "NEEDS_USER";
      request_id: string;
      reason: AutomaticBuildUserDecisionReasonV1;
      message: string;
      choices: Array<{
        choice_id: string;
        label: string;
        consequence: string;
      }>;
      projection?: AutomaticBuildUserDecisionProjectionV1;
    }
  | {
      kind: "DONE";
      summary: AutomaticBuildCompletionSummaryV1;
    };

interface AutomaticBuildStepResponseV1 {
  version: "automatic_build_step.v1";
  action: AutomaticBuildStepActionV1;
}
```

`AutomaticBuildStepResponseV1` 顶层禁止出现以下字段:

```text
command / cwd / path / sha256 / byte_length / semantic_prompt / extractor_prompt / envelope
candidate / task_input / receipt_body / plan_digest / policy_set_digest / proof_digest
```

`NEEDS_USER.message` 是代码生成的有界用户可见说明；`projection` 只投影用户作决定所需的计划、Pass2、预算、质量或恢复摘要。需要授权的原因提供有限 choices，纯外部阻塞可以返回空 choices，但不得夹带可执行命令让 Codex 自行解释。

### 3.2 调用输入

```ts
interface AutomaticBuildStepRequestV1 {
  version: "automatic_build_step_request.v1";
  invocation_ref: string;
  available_agent_slots: 0 | 1 | 2 | 3;
  decision?: {
    request_id: string;
    choice_id: string;
  };
}
```

`invocation_ref` 由明确的构建入口创建并持久化，绑定 target、BuildPlan ref、质量/预算参数和最大并行度。Codex 原样回传，不解析其内部字段。任何改变 target、计划候选、Pass2、质量或预算的操作都必须由权威入口创建新 revision 或形成 `NEEDS_USER`，不能靠 root 修改命令行参数。

`decision` 只接受上一条仍新鲜的 `request_id + choice_id`。Build Engine 在消费时重读当前 Reader-private plan/context，将选择原子绑定当前 digest；过期选择返回新的 `NEEDS_USER(plan_changed)`，不得让 Codex比较 digest。

### 3.3 Driver reducer

单次 `build.step` 在一个有界 transition budget 内持续执行纯确定性步骤，直到遇到外部边界:

```text
read invocation + authoritative disk state
  -> verify release/protocol internally
  -> compile/recompute preflight internally
  -> consume fresh user decision if present
  -> inspect active dispatch/task/private-artifact state
  -> run eligible close + postcondition verification internally
  -> replan internally
  -> stop at exactly one boundary:
       spawn required       => SPAWN_EXECUTORS
       external work active => WAIT
       user authority needed=> NEEDS_USER
       all declared outputs => DONE
```

约束:

- 每次调用从磁盘重算，不接受调用方上报“receipt 已成功”或“stage 已关闭”。
- transition budget 耗尽但仍可继续的内部工作返回短 `WAIT(backoff)`，不得抛出无界循环。
- `SPAWN_EXECUTORS` 发布前先持久化每个 ref；相同状态重放返回同一 ref 集合。
- 同一 ref 的并发 `executor.open` 只有一个能取得执行权，其余得到幂等 active/terminal 结果。
- Agent 返回文本只表示 harness 生命周期结束；driver 仍以 mailbox/receipt/artifact 为真相。
- `close_stage` 不再成为外部 action；driver 直接调用结构化 close API并在同次或下次 step 中 replan。
- 旧命令 stdout 继续供兼容测试和 rollback 使用，但新 skill 不读取它们。

### 3.4 用户决策原因

首版 allowlist 至少覆盖:

```text
plan_confirmation_required
plan_changed
pass2_choice_required
budget_exceeded
low_confidence_wall_budget
wall_budget_exceeded
executor_unavailable
foundation_required
legacy_migration_required
quality_gate_failed
retry_exhausted
executor_instability
installation_incompatible
```

内部 `preflight_required/evaluation_required/evaluation_changed/reconfirm_build_plan/retry_plan/migrate_policy` 不再直接暴露。Driver 将它们归并为稳定用户原因和有界 choices；可自动重算的状态直接重算，只有授权边界才停在 `NEEDS_USER`。

## 4. Executor 目标接口

### 4.1 Opaque handoff

`opaque_handoff_ref` 是 code-issued、ASCII、有界、原样传递的 locator。它不是 filesystem path，也不向 root 暴露 workspace、dispatch id、attempt、hash 或 mailbox identity。

Build Engine 持久化的 ref record 至少绑定:

```ts
interface AutomaticBuildOpaqueHandoffRecordV1 {
  version: "automatic_build_opaque_handoff_record.v1";
  opaque_handoff_ref: string;
  kind: "public_dispatch" | "private_artifact";
  target_ref: BuildTargetRefV2;
  owner_identity: unknown;       // versioned dispatch/task identity
  handoff_path: string;          // code-private
  handoff_sha256: string;        // code-private
  handoff_byte_length: number;   // code-private
  issued_at: string;
}
```

这些字段只存在磁盘记录和代码内部，不进入 `build.step` 的 action。

### 4.2 `executor.open`

专用 subagent 的第一个固定动作只有:

```text
executor.open(opaque_handoff_ref)
```

代码在返回任何语义输入前原子完成:

1. ref version/size/字符集与 lookup；
2. target/private-root 边界、realpath、symlink 与 publish marker；
3. handoff 存在、普通文件、byte limit、SHA-256 与 strict JSON；
4. prompt hash、dispatch run/manifest 或 private task/plan/artifact identity；
5. 当前 lease/attempt/terminal 状态和重复 open；
6. create-only open/claim record，或返回已有 active/terminal 状态。

Root 和 executor 均不再执行 `Test-Path`、`path.relative`、hash、长度、JSON parse 或 identity 比较。消费端重验仍发生，只是发生在 `executor.open` 内。

### 4.3 语义会话

`executor.open`/后续 session step 只向专用 subagent 暴露三态:

```ts
type AutomaticBuildExecutorSessionActionV1 =
  | {
      kind: "GENERATE";
      opaque_session_ref: string;
      semantic_prompt: string;
      semantic_input: unknown;
      output_contract: unknown;
    }
  | { kind: "WAIT"; retry_after_ms: number }
  | { kind: "DONE"; status: "committed" | "retryable_failure" | "interrupted" };
```

Agent 对 `GENERATE` 只做一件事:依据 `semantic_prompt + semantic_input + output_contract` 产生 candidate，并通过 code-owned candidate sink 交回 `opaque_session_ref`。代码负责:

- 建立/复用 attempt mailbox 与 lease；
- UTF-8/BOM/JSON/schema/size/hash 规范化；
- candidate staging、writer、quality/evidence gate 与 submit；
- heartbeat、failure receipt、dispatch progress、下一 work unit；
- 私有 artifact 的 plan/blueprint/source/evidence identity 重验；
- terminal receipt 与 resume。

`GENERATE` 不是、也不得包含 `automatic_build_executor.v1`。因此现有 extractor prompt 顶部的兼容条件“when the caller supplies an envelope”不会激活，Agent 走其既有 ordinary strict-JSON output contract；六个 prompt 文件无需改字节。Session wrapper 负责把生成结果交给 code-owned sink，并禁止 candidate 出现在 subagent final。

第一版允许 candidate sink 在 executor 私有上下文中继续使用临时 source file，但 canonical mailbox path、命令数组和 identity 不得暴露给 root；后续可改为 stdin/原生 tool，不改变 `build.step` 或 `opaque_session_ref` 合同。

### S3 Public executor session 与 receipt 收口（完成 2026-08-08）

**做**:让 executor session 依次领取 public work unit、接受语义 candidate，并由代码完成 input/candidate/submit/fail/heartbeat/finish；`build.step` 只重读 durable state。

**不变量**:

- candidate 只存在 executor/session/mailbox 边界；root action、日志与 subagent final 禁止正文。

**不做**:不改 semantic prompts、writer、schema、quality floor 或最大尝试次数。

**完成判据**:完整 public dispatch 从 opaque ref 到 terminal receipt 全绿；重复 submit、candidate 冲突、executor 中断和跨会话 resume 均由确定性测试覆盖。

**实施结果**:

## 9. Definition of Done

```text
done =
  root_action_surface_is_four_kinds
  AND semantic_planning_remains_in_codex
  AND model_inference_remains_in_harness
  AND build_state_machine_is_code_owned
  AND producer_and_consumer_gates_remain
  AND root_never_validates_handoff_or_receipts
  AND executor_only_handles_generate_actions
  AND candidate_never_crosses_root
  AND mailbox_lease_retry_quality_semantics_are_unchanged
  AND private_artifact_identity_is_code_validated
  AND old_protocol_has_bounded_rollback
  AND packaged_and_resume_tests_pass
  AND freshness_simplification_is_deferred
```

任一项为 false，不得以“skill 已缩短”“subagent 看起来成功”或 LLM 自评宣布完成。
