## 0. 对齐确认单

**FrozenIntent**:用一个 ADR 和一份可独立接手的切片方案解决模型工作单元不可路由问题。方案必须同时覆盖 canonical source/LID 边界、Pass1、profile sidecar、Build Engine Sidecar、策略迁移、`close` 成功语义和结构化恢复;不通过提高阈值、截断正文、重切 LID 或降低质量门禁绕过。成功标准是任一模型工作单元在 task/lease/dispatch 前已有可复验预算证明，真实触发 EPUB 保持 source/LID identity 不变并能从 profile sidecar 继续到 BuildPlan 的下一动作。

## 1. 已证实根因与非根因

### 1.1 当前 LID 是结构块粒度

`segment()` 消费各 source adapter 的 `SourceBlock[]`:heading 建 chapter/section 容器并生成标题叶子，其他 block 生成 paragraph/code/table/image/formula 叶子。不同来源的 leaf 边界为:

| 来源 | 当前叶子边界 | 不作为 LID 的边界 |
|---|---|---|
| EPUB | XHTML `p/li/blockquote`，以及 `pre/table/img/math` | 句号、CSS 换行、页面和模型 token 窗口 |
| Markdown | CommonMark/GFM paragraph、list item、code、table、image、math | 视觉自动换行和模型 token 窗口 |
| paper PDF | 可信 reconciled Markdown 的上述 block | PDF 页、行、glyph 和 bbox;这些只参与视觉对齐 |

所以真实 EPUB 是触发样本，不是专属修复点。任一 adapter 都可能产生超长 paragraph/list item/code/table/formula block;预算路由必须位于稳定 LID 之后、模型调用之前。

### 1.2 真实触发链

现有触发 EPUB 包含 37,897 个 canonical source 字符、34 个 LID node 和 4 个 Pass1 window，没有 `Window.overBudget`。其中 paragraph LID `1.7.2` 的 UTF-16 span 为 `[5629,13111)`，正文估算 6,992 token:它低于 Pass1 12k，却高于 profile discourse 5k。

```text
EPUB <p> -> one SourceBlock -> one leaf LID 1.7.2
  -> splitWindows(max=12000) accepts 6992-token leaf
  -> Pass1 closes
  -> profile sidecar groups only between LIDs(max=5000)
  -> single LID cannot flush smaller
  -> buildAutomaticBuildSnapshot throws before action/needs_user exists
```

`Window.overBudget` 允许“单个叶子超过该阶段窗口硬闸但继续形成窗口”。这可保留为 source 结构诊断，却不能再作为模型执行许可。

### 1.3 预算证明与真实输入不一致

profile router 当前用 packet identity 的 stable JSON 估算 token，而 `profile-sidecar-input.ts` 实际还会输出 semantic-unit header、字段和 `TEXT` marker。Pass1、Pass2 和 BookStructure 也分别在不同位置组装或估算输入。现状没有一个函数能同时证明“executor 读取的字节、input hash、prompt/protocol/output reserve 和输入硬闸”一致。

只给 `WorkUnitCostV1.estimated_input_tokens` 加限制仍不够:cost 是调度估计，不是可验证的物理输入证明。

### 1.4 Pass1 迁移缺少 policy generation

Pass1 仍绑定 `pass1_window.v1`、数字 window id 和 `.build/pass1/<id>.json`;stage policy lock 又固定写在单一 create-only 路径。router 版本升级会触发 `policy_mismatch`。现有 legacy migration 只能区分 legacy v1 与 policy-bound v2，不能记录旧 v2 generation 到新 policy set 的逐单元采用或重建。覆盖旧 lock 或把旧 envelope 直接标成新鲜都会破坏 freshness 审计。

### 1.5 profile sidecar 不能直接拼接分片输出

现有 prompt 要求每个 eligible paragraph LID 输出一个 discourse item，公开 `discourse_index.json` 也按原 LID 表达。若同一 LID 的两个模型输入片各自产一个最终 item，再把数组连接起来，会造成重复 LID、冲突分类和虚高的 emitted-item/coverage 指标。因此超长 discourse LID 必须使用“片段观察 -> LID reduce -> 唯一最终 item”，不能把重复条目称为合并。

### 1.6 `close` 只检查发布前条件

当前 `close` 先写质量报告、运行 stage batch，随后写 metrics。stage batch 虽调用 `publishAutomaticBuildArtifactSet`，但 wrapper 没有把本次 publication receipt、发布后的公开文件摘要、重建 snapshot 的 `stage.closed` 和 freshness digest 绑定为一个成功结果。子脚本 exit 0 仍可能被调用方误解为阶段或整本 BuildPlan 完成。

### 1.7 明确非根因

- 原 EPUB 合法且可确定性解析;不需要重导入、修书或按句重建 LID。
- `1.7.2` 未超过 Pass1 12k 当前硬闸;Pass1 关闭不是伪成功的直接证据。
- 故障发生在 planner/router，尚未进入 Provider、executor、lease 或 semantic attempt。
- BuildPlan 总预算和 dispatch 总 score 不能替代单次输入可路由性。
- 提高 profile 5k、截断 1.7.2 或让 executor 临场切分都不能提供可复现覆盖与恢复。

## 2. 冻结边界

### 2.1 必须保持

1. EPUB/Markdown/paper reconciled source 的字节权威、source fingerprint、SourceBlock 和 LID tree 不因本方案改变。
2. 模型输入片是 engine-derived 内部单位，不进入 Reader 引用、批注、Book MCP 或 public artifact evidence schema。
3. 所有 candidate 中的 `source_lid`、occurrence、target/evidence LID 继续只引用原 LID。
4. 同一被切 LID 的 core span 按 canonical source UTF-16 `[start,end)` 坐标完整、不重不漏;overlap 只扩上下文，不计覆盖。
5. input CLI 必须输出预算证明所哈希的同一份字节;router、task、lease、executor 不得各自重新拼一版。
6. 任一 model-eligible work unit 缺少有效预算证明时，不得创建新 claim、lease、dispatch 或 semantic attempt。
7. Pass1/profile sidecar 公开 schema 保持;分片中间观察不冒充公开最终产物。
8. 旧 policy lock、task artifact、attempt、lease、receipt append-only 保留;迁移不得覆盖或删除历史。
9. BuildPlan 仍是授权权威:精确采用可保持 reuse，需重建公开产物或突破确认预算时走既有 plan gate。
10. `full` quality floor、artifact/hash/schema gate 和 publication 原子性只可保持或收紧。
11. Node、packaged Sidecar 和薄插件必须消费同一 renderer、proof validator 和恢复合同。

### 2.2 明确不做

- 不把一个原 paragraph 持久化成多个新 paragraph/LID。
- 不为当前故障修改 EPUB/Markdown/PDF adapter 的 canonical 分块规则。
- 不把句子、token window 或模型 work-unit id 暴露为 citation anchor。
- 不允许 `--allow-partial` 关闭 automatic-build 阶段。
- 不用 overlap 重复量、fragment 数或 reducer 中间项抬高质量覆盖率。
- 不把 raw source、candidate、stderr、stack、任意绝对路径或私有目标写入恢复信封。
- 不因 router 升级重建整个书库;只处理当前目标的受影响 policy generation。
- 不让 LLM 自评“切分完整”或“close 成功”;全部交给 span、hash、schema、receipt 和 snapshot 检查。

## 3. 目标合同

### 3.1 数据流与唯一权威

```text
source adapter -> canonical source + SourceBlock[] -> segment() -> stable LID tree
  -> stage router -> ModelInputSlice[] / artifact-reduction dependencies
  -> one deterministic renderer -> exact input bytes
  -> budget proof + input hash -> WorkUnitDescriptorV3
  -> preflight reproof -> task/lease/dispatch -> executor input
  -> semantic artifact generation -> coverage/reduction gate
  -> stage quality -> publication -> post-close snapshot -> plan/next
```

source adapter 和 `segment()` 不接收模型预算。router 只能引用 canonical source 区间;renderer 是输入字节、input hash 和 budget proof 的共同权威。input CLI 只重放 descriptor 绑定的 renderer，不重新运行可漂移的 routing 决策。

### 3.2 模型输入片

```ts
interface ModelInputSliceV1 {
  version: model_input_slice.v1;
  source_fingerprint: string;
  parent_lid: string;
  ordinal: number;
  core_span_utf16: { start: number; end: number };
  context_span_utf16: { start: number; end: number };
  boundary_kind: whole_lid | sentence | punctuation | line | grapheme;
  core_sha256: string;
  context_sha256: string;
}
```

`core_span_utf16` 和 `context_span_utf16` 都是 canonical source 的绝对半开区间。context 必须包含 core;whole-LID 单元默认二者相等以保持旧 renderer 字节。分片输入若使用 overlap，renderer 必须显式区分 `CONTEXT_BEFORE/CORE/CONTEXT_AFTER`，模型只可为 core 提议内容，证据值仍为 `parent_lid`。

### 3.3 确定性分片与覆盖

```text
route(lid, render, budget):
  if prove(render(whole_lid)).within_limit:
    return [whole_lid]

  boundaries = safe_boundaries(lid.kind, canonical_source)
  while cursor < lid.span.end:
    choose the farthest deterministic boundary whose rendered bytes fit
    if no boundary can fit: return blocked(model_input_unsplittable)
    emit core=[cursor,end), bounded context around core
    cursor=end

  assert exact_core_partition(lid.span, emitted cores)
  return emitted
```

safe boundary 优先级按 block kind 固定:

| LID kind | 可切边界 | 不可安全切时 |
|---|---|---|
| paragraph/标题/list/blockquote 投影 | sentence -> punctuation -> whitespace -> grapheme | renderer 固定开销已超限则结构化阻塞 |
| code | line;保持 UTF-16/Unicode 边界 | 单个超长代码行默认阻塞，不静默腰斩语义 token |
| table | row，再由 stage-native table router 决定 cell | 单行超限则阻塞 |
| formula/image | 原子 | 超限则阻塞并报告 kind，不截断 MathML/asset metadata |

覆盖检查只看 core:

```text
sorted(core)[0].start == parent.span.start
every previous.end == next.start
sorted(core)[last].end == parent.span.end
sum(core.length) == parent.span.length
```

context overlap 不进入等式。同一 source fingerprint、router policy 和预算必须生成相同 slice identity、切点和 digest。

### 3.4 精确 renderer 与预算证明

```ts
interface ModelInputBudgetProofV1 {
  version: model_input_budget_proof.v1;
  estimator_version: string;
  render_contract_version: string;
  router_version: string;
  prompt_sha256: string;
  rendered_input_sha256: string;
  estimated_rendered_tokens: number;
  stage_body_limit_tokens: number;
  executor_context_floor_tokens: number;
  prompt_reserve_tokens: number;
  protocol_reserve_tokens: number;
  output_reserve_tokens: number;
  safety_margin_tokens: number;
  effective_body_limit_tokens: number;
  status: within_limit;
  proof_digest: string;
}
```

```text
context_body_limit
  = executor_context_floor
    - prompt_reserve
    - protocol_reserve
    - output_reserve
    - safety_margin

effective_body_limit = min(stage_body_limit, context_body_limit)
within_limit = estimate(exact_rendered_bytes) <= effective_body_limit
input_hash = SHA256(exact_rendered_bytes) = rendered_input_sha256
```

router 使用发布版支持的保守 executor context floor 生成证明;preflight 在选定 model/provenance 后重新验证，能力更小只能返回结构化阻塞，不能降低 reserve。prompt/protocol 的真实字节必须由 release/doctor 测试证明不超过各自 reserve。

`WorkUnitCostV1` 继续服务批次选择和总成本预测，但必须从已验证 proof 派生 `estimated_input_tokens`，不得成为 proof 的输入权威。

### 3.5 Model work-unit v3

```ts
type ModelInputBasisV1 =
  | { kind: source_slices; slices: ModelInputSliceV1[] }
  | {
      kind: artifact_reduction;
      dependency_artifacts: Array<{ work_unit_id: string; artifact_hash: string }>;
      parent_lids: string[];
    };

interface WorkUnitDescriptorV3 {
  version: automatic_build_work_unit.v3;
  target: BuildTargetRefV2;
  stage: WorkUnitStage;
  work_unit_id: string;
  kind: WorkUnitKind;
  input_basis: ModelInputBasisV1;
  input_hash: string;
  input_budget_proof: ModelInputBudgetProofV1;
  policy_fingerprint: ExtractionPolicyFingerprintV1;
  evidence_lids: string[];
  dependencies: Array<{ artifact: string; sha256: string }>;
  cost: WorkUnitCostV1;
  aggregation?: { parent_lid: string; role: fragment | reduce | final };
}
```

deterministic skip 不是模型工作，不要求伪造 proof;任何 eligible v3 descriptor 必须有 proof。v2 descriptor 保持可读和可审计，升级后不得创建新的 v2 claim;已领取 v2 lease 可在原 policy generation 内完成，迁移必须等待其 terminal 或过期，不能偷换 lease 输入。

reducer 也属于模型工作，必须对依赖 artifact 渲染出的真实字节生成 proof。依赖 artifact hash 变化会改变 reducer input hash 和 work-unit identity。

### 3.6 Stage policy set 与迁移

分片、普通抽取和 reduce 可能使用不同 prompt/schema，单 stage 单 fingerprint 不再足够。新 generation 冻结受限 policy set:

```ts
interface AutomaticBuildStagePolicySetV2 {
  version: automatic_build_stage_policy_set.v2;
  target_ref: BuildTargetRefV2;
  stage: SemanticBuildStage;
  members: Array<{
    kind: WorkUnitKind;
    extractor: SemanticExtractor;
    policy_fingerprint: ExtractionPolicyFingerprintV1;
  }>;
  policy_set_digest: string;
  frozen_at: string;
}
```

dispatch 继续只聚合相同 target/stage/kind/policy 的 work unit。quality gate 允许一个已冻结 policy set 内的多个成员，不再把合法的 fragment/reduce kind 误报为 `mixed_policy_generation`;policy set 外的 fingerprint 仍 fail-closed。

旧单文件 lock 保留只读;新 policy set 和 task artifact 使用 digest-qualified create-only generation 目录。当前 generation 由当前 release policy set + 有效 migration receipt 决定，不靠可覆盖的 `active=true` 文件。

迁移 receipt 对每个新 work unit 只允许:

| 决策 | 必须同时满足 | 结果 |
|---|---|---|
| `adopt_exact` | target/source 相同;渲染输入字节相同;prompt/schema/quality 相同;新 proof 通过;旧 artifact hash 有效 | 通过 receipt 引用旧 envelope，不改写旧文件 |
| `rebuild` | 任一输入片、prompt、schema 或质量策略不同 | 只在新 generation 生成 artifact |
| `deterministic_skip` | 当前 router 给出稳定 skip code/evidence | 不创建模型任务 |
| `blocked` | 有 active lease、冲突 receipt、不可切原子输入或预算仍放不下 | 返回结构化恢复，不冻结半迁移 |

若全部 public-contributing payload 可精确采用且既有 publication receipt/hash 匹配，BuildPlan 的 reuse 可保持;否则 public artifact 不再 fresh，必须由既有 `build_plan_freshness_drift`/预算门禁形成 successor plan，不能静默把 reuse 改成 create。

### 3.7 Pass1 分片与归并

Pass1 v2 保持 whole-window 快路径，只有单个叶子使真实 renderer 超限时才进入:

```text
pass1_source_slice[0..N]  # 各自输出现有 Pass1 nodes/edges，evidence 仍为 parent LID
  -> deterministic graph merge/dedup
  -> pass1_lid_stitch     # 读取有界 fragment artifacts，补跨片局部关系
  -> existing whole-book merge/gate
```

whole-window renderer 字节不变的单元可 `adopt_exact`;数字 window artifact 只作为旧 generation ref。fragment core 用有限上下文 overlap 缓解边界损失，stitch 仍须预算证明;极端多 fragment 时按稳定 artifact hash 构造分层 stitch tree。fragment/stitch 数不能成为 Pass1 eligible coverage 分母，质量仍按原证据 LID 与最终节点/边检查。

### 3.8 profile sidecar map/reduce

未超限的 discourse group 和 formula unit 保持现有公开语义。超限 paragraph LID 走:

```text
profile_sidecar_discourse_fragment[0..N]
  -> bounded ProfileSidecarDiscourseObservationV1
  -> profile_sidecar_discourse_reduce tree
  -> exactly one final TechnicalLearningDiscourseItem(parent_lid)
```

fragment observation 是 engine-private intermediate artifact，只记录受限分类候选、摘要片段、关系候选、core digest 和原 LID，不进入 `discourse_index.json`。reduce 输入只来自已验证 fragment/reduce artifact，不重新读取任意路径或聊天正文;根 reducer 必须产唯一 final item。若中间观察总量仍超限，按 source ordinal 和 artifact hash 分组形成多层 reduce，每层重新证明预算。

公开门禁要求每个 eligible 原 LID 恰有零或一个最终 discourse item;零项只可由现有确定性 skip 或通过的低信息质量规则解释，多个 final item 一律 integrity failure。formula/image 等原子单元超限时结构化阻塞，不截断。

### 3.9 结构化恢复信封

```ts
interface AutomaticBuildRecoveryEnvelopeV1 {
  version: automatic_build_recovery.v1;
  phase: routing | preflight | migration | close | post_close;
  code:
    | model_input_unsplittable
    | budget_proof_invalid
    | executor_context_too_small
    | policy_generation_migration_required
    | policy_generation_conflict
    | source_slice_coverage_invalid
    | build_plan_budget_changed
    | publication_receipt_invalid
    | stage_close_postcondition_failed;
  stage?: AutomaticBuildStage;
  target: { book_id: string; profile_id: string; input_fingerprint: string };
  router_version?: string;
  policy_digest?: string;
  affected_work_units: Array<{
    work_unit_id: string;
    evidence_lids: string[];
    estimated_tokens?: number;
    limit_tokens?: number;
  }>;
  retryable: boolean;
  recovery_actions: Array<
    retry_plan | migrate_policy | reconfirm_build_plan |
    upgrade_executor | inspect_publication
  >;
}
```

affected work-unit 与 LID ref 均有固定数量/长度上限，超出只给 count + digest。信封拒绝 source text、candidate、prompt、raw command、stderr、stack、任意 path 和未知字段。

精确采用或已确认预算内的确定性 generation migration 可自动写 create-only receipt 后重新 plan;只有预算/计划授权变化、冲突 generation、不可切原子输入或无法证明 publication 时才返回 `needs_user`。可预期 domain block 不再从 `plan` 抛裸 Error。

### 3.10 质量与覆盖报告

`automatic_build_stage_quality_report.v2` 在现有 integrity/quality 字段外增加:

```text
routing.policy_set_digest
routing.eligible_model_units
routing.proven_model_units
routing.invalid_or_missing_proofs
coverage.parent_lids
coverage.expected_core_utf16
coverage.covered_core_utf16
coverage.gap_utf16
coverage.core_overlap_utf16
coverage.coverage_digest
reduction.fragment_units
reduction.final_units
reduction.missing_or_duplicate_parent_lids
```

gate 必须同时满足:

```text
all required model units terminal and policy-fresh
AND every model unit has a valid proof
AND every split parent core is exact-cover
AND every reduction dependency closure is fresh
AND public contributor cardinality is valid
AND existing integrity gate passes
AND selected semantic quality floor passes
```

fragment、overlap 和 reducer 中间产物只进入执行完整性，不进入 grounded-unit 或 emitted-item 分母。这样切得更细不会自动提高质量分。

### 3.11 `close` 成功结果

```ts
interface AutomaticBuildStageCloseResultV1 {
  version: automatic_build_stage_close_result.v1;
  status: closed;
  stage: AutomaticBuildStage;
  target: { book_id: string; profile_id: string; input_fingerprint: string };
  quality: { report_digest: string; gate_status: passed };
  publication: { transaction_id: string; receipt_digest: string };
  postcondition: {
    stage_closed: true;
    policy_set_digest: string;
    coverage_digest: string;
    freshness_digest: string;
    public_artifact_set_digest: string;
  };
  next: replan;
}
```

执行顺序固定为:

```text
pre-close quality/coverage
  -> capture stage batch
  -> validate matching publication receipt and public bytes
  -> rebuild snapshot from disk
  -> recompute quality/coverage/freshness
  -> write create-only close result
  -> return next=replan
```

任一步失败返回 §3.9 的 bounded recovery。调用方收到 `status=closed` 后仍必须重新 `plan/next`;只有下一 action 为 `done` 才能汇报整本构建完成。

| source/LID identity 不变 | source fingerprint、SourceBlock/LID/span digest 前后相等 | 禁止 migration/close |
| renderer 是唯一输入权威 | CLI stdout SHA-256 = descriptor input hash = proof rendered hash | `budget_proof_invalid` |
| 所有 eligible unit 可路由 | preflight `proven_model_units == eligible_model_units` | 零 claim/dispatch |
| split parent exact cover | gap=0、core overlap=0、covered=expected | `source_slice_coverage_invalid` |
| reducer closure 新鲜 | 每个 child artifact hash 与 descriptor dependency 相等 | stage integrity fail |
| profile parent 唯一 | eligible 原 LID 的 final item cardinality 为 0/1，1 为正常产出 | duplicate/missing violation |
| policy 历史 append-only | 旧目录树 digest 不变，新 receipt create-only | `policy_generation_conflict` |
| BuildPlan 授权不漂移 | reuse freshness、预算 receipt、plan digest 对齐 | `needs_user` 再确认 |
| 质量分母不受切片数影响 | 1/2/20 fragment 的 parent/grounded 分母一致 | quality report fail |
| close 只认发布后状态 | receipt + public bytes + post snapshot + freshness digest | 无 closed result |
| recovery 有界且脱敏 | strict schema、大小上限、forbidden sentinel 扫描 | 协议拒绝 |
| Node/Sidecar/安装态同构 | canonical JSON、input bytes、proof/close digest parity | release fail |

每刀至少运行定向测试与 `pnpm -C packages/core typecheck`。BR8 起运行 `pnpm -C packages/core test -- automatic-build model-input profile-sidecar pass1`；BR10 起重建 Sidecar 并运行 `node apps/desktop/scripts/smoke-automatic-build-parity.mjs` 与 `node apps/desktop/scripts/assert-plugin-release.mjs`；BR11 才运行 Windows package/install 和隔离真书回放。最终再跑 Core 全量；并发 wall-clock timeout 必须以同文件单 worker 复跑区分环境噪声，不能修改断言或门槛。
