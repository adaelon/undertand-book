# 预构建工作台与流程

## 定位

Build Workbench 是 paper profile 的 reader 前置构建控制面。它接收未信任的 `paper.md + paper.pdf`，持久化输入、任务、人工决定和运行审计，再调用固定阶段运行器；只有确定性 artifact/hash/schema gate 可以把产物交给 reader。

核心边界：

```text
LLM / executor -> 候选、修订建议、结构抽取
用户决定      -> 来源复核选择与明确终裁
确定性代码    -> 指纹、schema、hash、LID、artifact 与 handoff 判定
```

LLM 不能直接声明一本书可信，前端状态也不能替代磁盘产物门禁。

## 主状态机

```text
draft_input
  -> source_reconciliation
      -> needs_user -> review decisions -> exactly one rerun
      -> deterministic trusted | valid manual_override accepted
  -> hybrid_foundation
  -> reader_ready
  -> optional paper projection stages
```

异常状态：

```text
input fingerprint changed -> stale_input
runner heartbeat expired   -> interrupted -> resume
provider/artifact failure  -> failed + failure summary + stdout/stderr
pending decision/permission -> needs_user
```

## 输入与持久化

1. Web 新建或打开论文工作区，导入 `paper.md + paper.pdf`。
2. Server 写 `.build/input/manifest.json`，记录 canonical 路径、SHA-256 与 Workbench config hash。
3. 相同 fingerprint 复用未完成 job；不同 fingerprint 的旧 job 标为 `stale_input`，仅保留审计，不参与当前门禁。
4. Job、events、decision requests、permission requests 和 active run 持久化在 `.build/jobs/`。
5. Stage 中间产物写 `.build/<stage>/`；reader 只读取通过门禁后写到书目录根部的正式产物。

## 阶段流程

| 阶段 | 主要输入 | 主要产物 | 完成门禁 |
| --- | --- | --- | --- |
| `source_reconciliation` | Markdown、PDF text geometry、fingerprint、review decisions | report、review draft、reviewed draft、stage `source.txt` | fingerprint 当前且 report 为 deterministic trusted 或 valid accepted |
| `hybrid_foundation` | accepted stage source、原始 PDF | 根 `source.txt`、`base.json`、`source_manifest.json`、PDF maps/alignment | source hash、manifest、schema、capability artifact/config hash 一致 |
| `pass1` | LID 窗口与 profile 规则 | 局部 graph 候选 | 只引用输入 LID，merge/gate 删除悬空锚点与坏边 |
| `paper_metadata` / `paper_lexicon` / `profile_sidecar` | 可信正文、LID、已有公共 sidecar | paper profile sidecars | schema、evidence LID 与 profile contract |
| `pass2` | graph、discourse/formula sidecar、候选 target | long-range edges 与 audit | 候选分类、端点、证据和 scope gate |
| `book_structure` / `paper_reading_guide` | 已门禁的公共 artifacts | 结构与阅读指南投影 | 不改写 source truth，输出通过各自 schema |

`paper_lexicon` 仍使用 V2 descriptor，但 `paper_lexicon_policy.v2 / paper_lexicon_cluster.v4` 不再复用旧 V1 scope：direct、fragment、reduce 和 deterministic skip 的 work-unit ID 都携带由 stage policy、router 与 prompt 计算的 scope digest；首次 claim 在 `.build/automatic-build/v2/policies/paper_lexicon/<policy_digest>.json` create-only 冻结完整策略。旧 `.build/automatic-build/v2/policies/paper_lexicon.json`、旧 task attempts 与 `.build/paper-lexicon/<legacy-id>.json` 只读保留。

Reader trust gate 在 `source_reconciliation + hybrid_foundation` 完成后成立；后续 projection stages 只能扩充 paper profile，不能回写或重新定义 `source.txt/source_manifest.json`。

## 来源复核

每个 unresolved block 同时展示原始 PDF 页、Markdown 渲染和 PDF 提取正文。用户可以采用 Markdown、PDF、候选修复、手工修订或保持阻塞。

批量 LLM 处理遵循逐项提交：

- 用户的一次点击授权逐项分析并立即记录合格的 `manual_edit`。
- 仅采用契约有效、非 `uncertain`、`confidence >= 0.8` 且 replacement 非空的结果。
- 成功项持久化；provider 失败、低置信、不确定和非法输出仍留给人工，不回滚已成功项。

全部决定可用后只运行一次 deterministic reconciliation：

```text
unresolved == 0
  -> deterministic trusted

unresolved > 0 && valid manual_override
  -> accepted reviewed draft
  -> residual diagnostics retained for audit
  -> no repeated review or automatic rerun
```

`manual_override` 必须同时满足固定 mode/policy、非空 `accepted_at`、残余计数等于当前 unresolved 数、`decision_count > 0`；stale fingerprint 永远优先阻塞。人工终裁不绕过后续 source hash、manifest、schema、LID 或 artifact gate。

## 执行与恢复

1. Web 选择 stage、executor 与 adapter mode，Server 写固定 run contract。
2. `adapter_mode=builtin` 以 `shell=false` 启动 `skills/build/workbench-stage-runner.ts`。
3. Runner 从 input manifest 和 durable job 读取输入，调用 `packages/core/src/workbench-stage-runner.ts`。
4. Runner 定期写 heartbeat，原子更新 job 和 stage events。
5. Server 每次 snapshot 都重新读取磁盘产物并计算 readiness，不信任 runner 的口头成功。
6. 超时 heartbeat 标为 `interrupted`；resume 使用新 run id 从持久化 stage 恢复。
7. Job、events 与 permission audit 有界保留；失败记录 stage、run、日志路径和 recoverable 状态。

## 抽取质量约束

经典预构建链仍遵循：

```text
source -> deterministic LID segmentation -> LID subtree windows
       -> Pass1 local extraction -> deterministic merge/gate
       -> profile sidecars -> Pass2 long-range classification
       -> BookStructure / PaperReadingGuide projections
```

Pass1 使用 `pass1-local-extractor`，profile sidecar 使用 `profile-sidecar-extractor`，Pass2 使用 `pass2-longrange-linker`。专门 extractor 不可用时应报告阻塞，不得用 generic sidecar、空泛公式解释或 reject-all 常规降级伪造完成。LID 是证据坐标；graph edge 连接 graph node id，discourse relation 才直接连接 LID。

## 需求驱动计划与使用统计

Reader trust gate 完成后，用户可以继续按需阅读、确认标准深读，或确认 reader-private 目标计划。昂贵执行仍只接受 confirmed `BuildPlan`；统计账本不产生授权，也不替代 Workbench job、automatic task mailbox 或 private artifact acceptance。

```text
read_now / confirmed BuildPlan
  -> plan_selected + frozen estimate
  -> reader_ready
  -> every terminal attempt cost (success and failure both retained)
  -> optional private artifact_accepted
  -> actual artifact_opened / artifact_cited
  -> deterministic replay(as_of, window_days=7)
```

账本位于 reader-private 根的 `<book_id>/usage/events/`，每个事件是独立的 create-only JSON 文件。相同 ID 与相同正文重放幂等；相同 ID 的不同正文、非法字段、超限文件、路径 identity 不符或 symlink 都 fail closed。删除某个 intent 时同步删除 plan ref 绑定该 intent 的事件，不删除公共 automatic task 或其他 intent 的历史。

事件只记录稳定身份、枚举、digest、revision、计数、token、耗时和时间。禁止写入 `user_goal`、artifact payload、LID/evidence list、quote、用户画像、模型/harness 细节或 task path。Server 自动记录计划选择和 private artifact acceptance；authorized controller 可以上报成本或把既有 `AutomaticBuildTaskMetricsV1` 桥接为成本事件；Reader 只允许上报 `reader_ready`、`artifact_opened` 和 `artifact_cited`。证据点击仍把 LID 交给 Reader goto，但统计请求只携带 artifact ID。

`GET /build_intent/usage` 以请求时钟为显式 `as_of`，固定返回 `read_now`、`standard_deep`、`goal_directed` 三组。估算与实际成本分栏；实际成本累加全部 committed/retryable_failure/needs_user/cancelled attempt；报告首次可读、首次目标产物、7 日 accepted/opened/cited 数与比率，以及每种 private artifact 的 token/墙钟成本。报告 digest 由 canonical JSON 计算，可由原始事件完全重放。
