# 完整 Agent 语义与动作评测

使用生产 `POST /agent/chat` 测量 Resident Agent。问题不附带金标准、参考 LID 或检索种子；Agent 自己决定调用哪些工具、如何追问工具结果、何时交付答案。

## 运行

```powershell
cargo build -p server --bin server
pnpm eval:semantic:test
node evals/semantic/agent-run.mjs --validate
# 沿用 .env 的 OPENCODE_API_KEY、OPENCODE_BASE_URL、FLUID_LLM_MODEL
node evals/semantic/agent-run.mjs --out evals/semantic/results/my-agent-run
node evals/semantic/agent-report.mjs evals/semantic/results/my-agent-run
```

`--book` 可指定书库，默认用户指定的 `.understand-book/quantification-essence`。`--only exact-02,source-02,restart-01` 用于接入预检；预检单列，不拼入主表。已存在的运行目录不可覆写。书库不随仓库发布。

服务与私有记忆按题隔离，不连接日常 Reader，不回写原始基座。程序沿用已有模型配置，调用会产生费用。主表至少包含 24 次 Chunk 请求；Agent 请求数由实际工具循环决定，不是每题一次。语义标注另需最多 52 次请求，其用量单列。每个 Agent 问答请求超时为 300 秒，失败保留；生产内部的重试、压缩、修复与内层模型请求全部经过记录器。

## 题集与比较范围

协议 `quantification-essence-agent-v1` 使用 32 题，定义在 [agent-dataset.mjs](agent-dataset.mjs)。

| 分组 | 数量 | 执行方式 |
| --- | ---: | --- |
| 原文定位、概念、跨章节、反例/对比、公式 | 各 4，共 20 | 两系统自然语言回答，必要事实与来源分别检查 |
| 证据不足拒绝 | 4 | 两系统明确承认本书未提供，不臆造答案 |
| 来源跳转 | 4 | Agent 自主找到原文并实际操作阅读器 |
| 重启恢复 | 4 | Agent 保存两条笔记、高亮、位置；进程重启及新聊天后自行恢复 |

前 24 题用于共同问答表，后 8 题是 Agent 专属能力表。沿用原实验 20 道问答、4 道来源和4 道记忆目标；拒绝题中的身份证/API 密钥问题换成训练随机种子/数据库地址，避免将隐私安全拒绝混同证据不足。其余两题询问原文未给出的未来审计收益及模型文件摘要值。旧版题集与结果保持不变。

## 两个系统

**Chunk RAG**：原文按 1000 UTF-16 字符分块、重叠 150 字符；中英 BM25，最多 6000 字符原文；一次模型调用，自然语言回答并标记提供的 chunk 来源。它是普通词法 RAG，不代表向量、混合检索或 Agentic RAG 上限。

**Resident Agent**：真实编译服务、默认 `OuterConfig` 与生产系统提示、动态工具发现、证据账本、来源编译、记忆和阅读工具。记录全部模型请求及工具轨迹，不强制某项工具必须使用，也不缩减生产工具面。默认主循环最多 12 轮；压缩、内层查询与答案修复可能增加请求。保持生产上下文策略，没有给 Agent 套 Chunk 的 6000 字符限制。

两系统同书、同配置模型、温度 0、同问题与阅读要求，交替运行顺序；提示、工具能力、上下文预算不同。本轮回答“完整产品相对普通 RAG 的效果/代价”，不能回答“单独增加图谱的因果收益”。后者需同一 Agent 循环的工具面消融。

## 指标

- **证据召回**：必要参考证据组被实际模型输入覆盖的比例。Chunk 使用实际输入块；Agent 从所有请求中的生产工具证据回执找回实际可见的原文，必须同时有 accepted evidence 与真实原文正文，不能凭 LID、图谱概述或搜索预览算完整回读。参考锚组是代理，不穷尽所有正确替代段落。
- **引用支持率**：必要事实中“回答正确且存在有效原文引用支持”的比例。没有引用计不支持；拒绝题没有事实槽，不进入此分母。Agent 引用须出现在最终 `answer_view` 且能经 `/agent/source.resolve` 解析为当前原文；仅在工具里生成过编号、或在答案中裸写编号，均不算可交付引用。
- **任务成功率**：24 道共同问答中全部必要事实与引用通过，或正确拒绝的比例。并列报告内容正确率以区分知识错误和引用交付失败。来源题额外要求真实阅读动作及目标视口；重启题有独立判据。
- **P95 延迟**：nearest-rank，从问答发起到完成；包含 Agent 内全部工具与模型调用，排除服务启动、预构建、事后状态核对与判分。超时和失败留在分母。
- **单任务 Token**：记录器捕获的所有实际 Provider `usage.total_tokens` 之和的均值，包含内层模型调用和修复。任何请求缺 usage 则报告 N/A，禁止用 Runtime 估计值或字符数补齐。

语义标注器只看到题目、字段定义、最终自然答案和有效引用，不看到系统名称、轨迹或标准答案值。它抽取枚举/数字/布尔值、逐字答句及支持来源 ID；确定性程序对比金标准、检查答句真实出现、来源有效、工具动作与最终状态。语义蕴含仍依赖模型标注，不能称作人工审核或纯确定性语义验证。标注请求用量单独记账，不计产品成本。

公开报告按 `natural-facts-v2-bold-normalization` 对全部原始答案统一重算：逐字比较忽略 Markdown 加粗分隔符 `**`，不改写用词、数值或引用。原始 `run.json`（包括早期逐字比较的临时分数）保持不变。使用非默认语料时，将路径作为报告命令的第二个参数。后台画像 review 请求也计入实际 Token，并在 `background_usage` 单列；服务退出后记录器等候已发出的请求完成，仍无 usage 才记 N/A。

## 重启契约

```text
空记忆 + 服务 A → Agent 保存/定位 → 读取实际持久记录
→ 关闭服务 A → 启动服务 B（同一记忆目录）→ 确认记录/位置恢复
→ 新建空聊天 → Agent 收到不包含原笔记答案的恢复请求
→ 确认原信息实际进入模型输入、Agent 原样复述、准备及恢复均成功
```

评测器不替 Agent 保存，也不把原笔记或目标 LID 放进恢复提问。状态读取不改变阅读器。服务的正常记忆注入也算观察，无需为了轨迹好看强制额外 `memory.recall`。笔记须在正确原文位置保存原内容；高亮须保存指定原句；位置须在重启前后保持可见和相同顶部位置。失败准备不跳过。

## 产物与限制

`run.json` 保存完整请求、回答、工具证据、标注和动作观察，仅在本地，Git 忽略。记录器不保存 HTTP 密钥或 Provider 独立推理字段。`summary.json`、`report.md` 只发布指标、工具计数与匿名逐题状态。题集原文不随公开结果分发。

单书开发集、每题每系统一次，尚无盲测和误差区间；标注器与被测系统用相同模型家族；核心事实支持不代表答案每句话均无幻觉。本轮测进程重启与新聊天，不是断电恢复或长期学习质量。来源操作测生产 API 状态，不包含前端点击路径的端到端 UI 测试。

基线 `2026-09-08-agent-v1` 使用本地开发机上已编译的修复前服务；测试期间未重编译该服务。测量期间设备仍有开发负载，延迟不代表空闲专用硬件或线上 SLA。后续编号列表误报的源码修复及单题验证单列，不重写这轮基线。

旧的固定检索策略实验及两轮结果见 [原方法](README.md) 和 [旧实验结论](findings.md)。

## LA8–LA9 同环消融复现

使用 `node evals/semantic/agent-run.mjs --ablation --out <新目录>`；固定程序通过 `SEMANTIC_EVAL_SERVER` 指定。该入口显式注入 `UNDERSTAND_BOOK_EVAL_ACCESS`，生产默认不注入。程序与源码快照必须在批次开始前固定，批次内不重编译替换。

24 道共同问答 × Text/Tree/Graph × 每题一次；按题号循环轮换三组顺序。三组共用 deepseek-v4-flash、温度 0、12 轮、300 秒、8,000 输出 tokens、120,000 累计实际 tokens、20,000 终答预留、12,000 UTF-16 唯一正文预算及原有 ToolExposure schema 限额。调用数不是轮数，终答和来源修复均计实际用量。已在途请求可超出累计上限，随后新采样停止；缺失 usage 的成本及预算满足状态记 N/A。

Text 为原文/词法；Tree 加 canonical 章节树和邻接；Graph 加概念和语义关系定位。共同关闭 query/synthesize、profile、memory、artifact 和模型 sidecar 环境，搜索和概念预览不提供原文正文。正文必须经相同 book.text 回读、证据闸与区间并集预算。不是默认完整产品的工具面。

完成后运行 `node evals/semantic/ablation-report.mjs <目录>`。程序按同一判分规则生成匿名配对结果，保留新增/失去成功、工具路径、实际成本、请求输出上限和在途超出；原始 run.json 不改写。`node evals/semantic/prebuild-report.mjs <书目录> <新目录>/prebuild.json` 只读现有书库，报告历史阶段计时、已有产物体积和缺失用量，不重建原书。单次开发集不能支持统计显著性或 README 的普遍图谱收益主张。

LA10 的真实前端连续场景使用 `node evals/semantic/continuous-reading.mjs <私有目录>`，走同一生产服务并使用独立记忆；完整行为状态与来源解析保存到本地。该场景补充基线缺少的前端点击验证，不反写基线。
