# 32 题循证阅读评测

**完整生产 Agent 评测请看 [AGENT_EVAL.md](AGENT_EVAL.md)**：真实 `/agent/chat` 自主工具循环、自然语言答案、实际来源跳转与 Agent 重启恢复。下面保留的是早期固定检索消融，不能作为完整 Agent 能力结果。

对用户指定的 `quantification-essence` 书库进行 **28 道阅读任务 + 4 道进程重启恢复任务**的可复现评测。目标是识别系统的优势和失败，不预设图谱一定优于分块检索。

## 运行

需要 Node.js 22+、Rust、已安装的仓库依赖，以及这份书库的 `source.txt`、`base.json` 和原有语义 sidecar。原书不随仓库分发；路径可通过 `--book` 指定。书库只读，服务使用新建的临时记忆目录，不接入你的日常 Reader。

```powershell
pnpm install
cargo build -p server --bin server
pnpm eval:semantic:test
node evals/semantic/run.mjs --validate --book ".understand-book/quantification-essence"

# 配置 .env 中的三个模型变量后，执行真实模型调用。
node evals/semantic/run.mjs --book ".understand-book/quantification-essence" --out evals/semantic/results/my-run
node evals/semantic/report.mjs evals/semantic/results/my-run
```

输出目录已有 `run.json` 时拒绝覆盖。默认每题每系统运行一次，56 次请求，不自动重试或剔除失败。可用 `--only exact-01` 做单题接入预检；预检不能替代全量结果。`--integration-only` 只检查真实 Reader 重启，无模型调用。

环境变量：`OPENCODE_API_KEY`、`OPENCODE_BASE_URL`、`FLUID_LLM_MODEL`，沿用项目现有命名；使用兼容 Chat Completions 和 JSON object 输出的服务。程序只记录模型名与服务 origin，不保存密钥。`SEMANTIC_EVAL_SERVER` 可指定已编译的 server 可执行文件。

## 冻结任务

| 类别 | 数量 | 判据 |
| --- | ---: | --- |
| 精确原文定位 | 4 | 正确事实 + 原文支持锚 |
| 概念解释 | 4 | 分类、定义、适用边界的事实槽 |
| 跨章节关系 | 4 | 同时回答不同章节的必要事实，有各自证据 |
| 反例 / 对比 | 4 | 区分相近概念、识别反例，不能只命中关键词 |
| 公式解释 | 4 | 从给定公式判断方向或计算倍率，有公式来源 |
| 来源跳转 | 4 | 答案通过后，实际跳转并回读对应原文 |
| 证据不足拒绝 | 4 | 明确拒绝且不生成事实字段 |
| 重启恢复 | 4 | 真实进程退出/重启，两条笔记、高亮、阅读位置恢复 |

题目与参考事实见 [dataset.mjs](dataset.mjs)。每个事实槽有类型/枚举、可接受答案和证据组。参考答案与证据锚只进判分器，模型只见问题、字段说明和检索结果。证据锚在调用模型前检查是否真实存在；没有参考锚的语料版本会显式报错，避免悄悄换书后继续打分。

这一版的“概念解释”评估的是定义、分类和适用边界能否正确落到事实槽，不评价自由讲解的完整性与教学效果。没有用模型给自己打分。

## 公平对照

两组读取同一份原文，使用相同的中英文 BM25 分词、同一模型、温度 0、同一提示词和 **6000 UTF-16 字符原文上限**。

- **Chunk RAG (BM25)**：1000 字符定长分块、150 字符重叠，全库 BM25 排序，在统一预算内提供原文。它是明确的词法基线，不代表最强向量/混合检索 RAG。
- **LID + Graph**：对原文叶子 BM25 排序，取前 4 个种子；调用生产 `book.context(granularity=far, k=128)` 获取树/概念/关系邻居；保留种子后对候选叶子词法重排，并通过生产 `book.text` 回读。图关系用于找内容，回答只消费原文。

这是 **检索策略对照**，不是完整 Resident Agent 对照；未启用模型查询规划、多轮工具探索或单独的向量基线，也没有把图谱标签作为事实灌进回答器。两组的实际输入 Token 可以不同：6000 字符是原文上限，不是总提示 Token 相同。

来源任务使用生成结果中的真实证据坐标，调用 `reader.goto`、`reader.state`、`book.text` 验证目标可见和原文一致。它测试定位底层接口，不代替用户可见的 `source.resolve/open` 弹窗 UI 测试。重启检查使用共享 Reader 能力，不把它归为任一检索器的优势，也不声称测到了 Agent 的自主记忆整合。

## 指标定义

- **证据召回**：24 道可回答任务的参考证据组宏平均。每组允许替代锚，实际输入区间完整覆盖其中一个即命中；拒绝题不进入分母。
- **引用支持率**：正确事实值 + 真实已提供引文 + 对应参考锚覆盖的引文数 / 全部生成引文数。对当前封闭任务是可复核代理指标，不能等同于开放式语义蕴含。若生成结果没有引文，报告 N/A；无引文的可回答任务无法成功。正确的替代表述或辅助引用可能不命中锚，不命中不代表造假。
- **任务成功率**：28 题中所有必要事实及证据都通过的比例，来源题另需定位成功，拒绝题另有判据。错误/超时留在分母。
- **P95 延迟**：nearest-rank，包含检索、工具、模型和来源定位。不含预构建、启动服务、加载原文或建立 BM25 索引。含失败任务耗时。
- **单任务 Token**：Provider 返回的 `usage.total_tokens` 的均值；缺失就 N/A，不用字符数填补。模型服务的缓存和推理计量由 Provider 决定。

任务成功只要求所有事实槽的必要证据齐全，额外引用不影响成功，但会进入引用支持率的分母。因此两者数值不能直接比较。

## 两次完整实验

- [首轮：逐字引用协议，1600 输出 Token 上限](results/2026-09-08-v1/report.md)。保留全部原始结果，包含公式转义、引文改写和输出截断失败。
- [第二轮：证据编号协议，4096 输出 Token 上限](results/2026-09-08-v2/report.md)。使用同一题集、同一检索器与原文预算，让模型选择已提供的证据编号，由程序绑定真实引文。该修正针对共同回答器，不是仅对图谱组调参。精确复跑首轮协议可加 `--answer-protocol quotes-v1`；默认第二轮为 `evidence-refs-v2`。

这两轮不是相同设置的重复样本，不能合并计算置信区间，也不能把差异全部归因于证据编号。后续调参必须新增运行目录，不覆写历史。

**结论：暂不支持图谱整体胜出。** 第二轮 Chunk / LID 严格成功数分别为 25/28 与 24/28；差距受召回缺口、分块边界及参考锚漏判影响。可定位的失败和下一步见[实验结论](findings.md)。

## 产物与复核

`run.json` 保存实际输入片段、返回引文、Provider usage、图谱工具轨迹、逐题判分及重启观察，仅保留本地并被 Git 忽略。`report.mjs` 输出可公开的 `summary.json` 和 `report.md`，保留事实值、证据坐标、用量、耗时、失败和判分细目，不分发原书全文或机器私有路径。

README 截图可在 `pnpm demo:prepare`、`pnpm build`、`cargo build -p server --bin server` 后用 `node evals/semantic/capture.mjs` 重新生成；需要已安装 Playwright Chromium。脚本用独立临时记忆创建演示笔记与高亮，再截取真实前端，不伪造模型回答。

原书标题为《你认为量化的本质是什么？》。测试描述该书的观点，不验证其金融论断。原书中重复数字、公式排版等输入噪声保留不变。单书 32 题属于开发集，没有独立盲测、重复采样或线上 SLA 保证；准备简历时应一并说明样本数和对照范围。
