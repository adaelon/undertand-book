# 完整 Agent 的失败链路

以下结论来自真实生产 `/agent/chat`，不是固定检索脚本。完整指标见 [Agent 报告](results/2026-09-08-agent-v1/report.md)，复现方法见 [协议](AGENT_EVAL.md)。

24 道共同问答的修复前基线：Chunk 成功 **22/24**，完整 Agent 成功 **13/24**。Agent 的参考证据召回为 88.5%，高于 Chunk 的 84.6%；但其 19/24 的内容正确中有 6 题未交付有效引用，另外 4 题返回未完成、1 题发生 `FINALIZATION_TOOL_PROTOCOL_VIOLATION`。主要缺口在检索之后的执行与交付闭环，不能用召回略高来代替整体成功。

## 普通动作请求的权限传播缺口

小样本 source-02 找到了 Hedge 的原文并交付可解析引用，但没有执行阅读器跳转；restart-01 找到了原文，却未能保存阅读笔记，新聊天当然也无法恢复它。后者不能解释为存储层在重启时丢失了已保存笔记。

代码原因：`crates/runtime/src/tool_exposure.rs:classify_turn_intent/seed_turn_tool_activations` 只对 `ExplicitGuidedRead` 标记明确写入意图；`stamp_task_need` 要求该标记才保留写入模式。普通“跳转/保存笔记/高亮”请求不在这条意图入口内，Agent 请求写入工具时仍会被降为只读。改变搜索词不能解除这个宿主条件。

后续修复应连接已有动作权限与明确用户操作意图，保持只读问答和否定操作的边界；不能在评测器里给 Agent 预先授予全部权限或替它调用写入接口。

正式基线同样是来源跳转 0/4、重启完整任务 0/4；四道重启的保存/定位准备都未通过，所以持久化子项标记为“未进入”。四次服务进程均真实替换，恢复前活动聊天均为空。

## 找到证据不等于交付成功

exact-04 已读到“不做预训练”的证据，最终却裸写来源编号，未形成 `answer_view` 引用。exact-03 的实际模型草稿已包含保留已退市标的的正确结论，生产交付链最后返回生成失败。主表以真正返回给用户的答案为准，不拿中间草稿替代最终交付。

后续应把来源编译失败、修复结果和最终可用性连在一条可复核链路上；对于已经绑定的来源编号格式错误，可以修复交付协议，但不能接受未回读或不存在的来源。

已据 exact-03 修复一个具体误报：根 LID `1` 与正常编号列表 `1. …` 碰撞，修复器删掉真实 LID 后，列表仍可能令第二次交付失败。新增回归确认普通编号列表可交付，而 `LID 1`、`[1]`、`第1节` 和内部多级编号仍按原合同校验。基线保留的是修复前版本；源码修复不反写历史分数。

来源/交付相关 25 项 Rust 测试通过。基线结束后重新编译当前服务，exact-03 的 [单题真实验证](results/2026-09-08-list-marker-fix-probe/report.md)通过：6 次模型请求、35.14 秒、52,490 Token，交付正确答案和可解析引用。单题验证与确定性回归相互补充，不是修复后全题成绩，也不用于声称整体性能提升。

## 失败后的恢复与退出成本

concept-02 的范围读取先触发 `LID_PROVENANCE_REQUIRED`，随后出现连续 `AGENT_NO_PROGRESS`，原文回读、上下文、查询/综合和来源呈现尝试均受到影响。这道题最终没有交付答案，消耗 104,708 Token、118.60 秒。它说明仅有证据闸与循环上限，并不能保证有效的错误恢复或及时退出。

后续应验证：已有定位仍可恢复为合法回读；若当前状态已无法取得任何新进展，应给出明确未完成结果并停止重复采样。不能为了提高分数去掉证据来源约束。

## 评测器修正与解释边界

原始语义标注有时省略答案中的 Markdown 加粗分隔符，逐字核对会误判内容错误。公开分数使用 `natural-facts-v2-bold-normalization` 对两组全部原始答案重算，保留原运行文件；只忽略 `**`，不替换词句或放宽来源要求。

本轮为开发集，不是独立盲测。Agent 与普通 Chunk RAG 的提示、上下文与工具能力不同，不能将差异归为图谱的单独收益。当前最值得展示的是完整链路的可复现测量与真实缺陷定位；尚不能把旧固定检索分数写成自主 Agent 的成功率。
